# 0.1 — Test Harness & Content Generator

## Goal

`index.html` + `harness.js` + `harness.css`: the single development and
manual-QA surface for every engine feature. Generates text and visuals on the
fly, zero network, `file://` friendly, no build, no npm. Must show every
combination of chapter length, gap, background size and stretch mode, parked
text slots — and must also provide *mechanical* QA probes so that 0.2–0.4
acceptance criteria are button-pressed, not eyeballed.

## Non-goals

- Not a production template. Keep it noisy and diagnostic.
- No lorem ipsum. Text must be position-readable (`R`, `3·12`, chapter labels,
  ruler ticks) so scroll position and wagon identity are obvious at a glance.
- No canvas-generated textures: inline SVG data URIs and CSS gradients are
  enough, synchronous, and give 0.2 a known box size without image decode.

## Architecture

- Classic `<script src="snowfall.js">` then `<script src="harness.js">`. No
  modules.
- Harness must work with the engine absent and must never assume `Snowfall`
  exists: every call is guarded (`window.Snowfall && Snowfall.refresh()`).
- All DOM built as one string, single `app.innerHTML = parts.join('')`, then
  one reflow. No per-node `createElement` loops.
- Config lives in `location.hash` (written with `history.replaceState` in a
  `try/catch`, because `file://` may refuse it — fall back to plain `hash=`).
  `seed` is part of the hash so a bug report is a copy-pasteable hash.
- Deterministic generation: `mulberry32(seed)` PRNG, no `Math.random()`.
- QA runs from in-page buttons (`QA: all`, per-probe buttons). No npm, no
  console needed. Node gates (`test/`) are an optional extra for CI, never a
  prerequisite for trusting a change on a real browser.

## Controls (`<form id="gen">`)

| id | values | meaning |
|---|---|---|
| `n` | 1..12 | chapter count |
| `len` | `tiny` 18 lines, `mono` 60, `huge` 220 | lines per chapter |
| `gap` | `zero` none, `same` fixed, `mixed` seeded random, `huge` >1 wagon | text lines between a heading and its `.snow-bg` — the axis that exposes parking bugs |
| `flow` | `overlay` 0, `screen` 100vh, `mixed` | wagon `data-gap`: flow footprint kept behind the wagon |
| `mode` | `cover` `tiled` `contain` `fixed` `auto` `mixed` | wagon `data-mode` |
| `size` | `256` `512` `1024` `mixed` | `data-size` for `fixed`/`auto` |
| `dir` | `none` `mixed` `top` `left` `right` `bottom` | `none`/`top` = default exit; `mixed` sprinkles; a named dir applies to every wagon |
| `nest` | `section` `flat` `both` | wrap chapters in `<section>` or emit loose nodes — proves no section tree is required |
| `stick` | `off` `top` `bottom` `both` | emit `.snow-stick` caption (top) / location tag (bottom) per chapter |
| `style` | `off` `on` | per-chapter `data-bg`/`data-fg`/`data-style` + `data-range` |
| `events` | `off` `on` | `script type="txt"` blocks per chapter |
| preset | `mixed` `mono` `tight` `draft` | `tight` = wagons with zero gap (coupled train); `draft` = the snippet from the draft file, verbatim |

Buttons: `regen` `top` `bottom` `next ch` `prev ch` `autoscroll` `QA: all`.
Checkboxes: `wireframes` `show engine state`.

## Generated DOM

Per chapter `k` with colour name `C` (red/blue/green/yellow/purple/checker):

```html
<section data-bg="#…" data-fg="#…" data-style="night" data-range="240">
	<h4 class="n">3</h4>
	<div class="snow-stick" data-park="top">ch3 · caption rides here</div>
	3·0<br>3·1<br>…                       <!-- line number = position proof -->
	<div class="snow-bg" data-mode="cover" data-size="512" data-dir="left" data-gap="0"
		style="background-image:url('data:image/svg+xml,…')" data-bg="#0f8">
	</div>
	R<br>R<br>R                           <!-- colour run after its image -->
	3·40<br>…
	<script type="txt" event="view">Snowlog("ch3 view")</script>
	<div class="snow-stick" data-park="bottom">ch3 · loc 40.7N</div>
</section>
```

Rules:

- `.snow-bg` is placed **after** its heading and text gap, and sometimes a
  second one free-floating between two lines — the free-placement case.
- `.snow-stick[data-park=top]` goes at chapter **start**, `[data-park=bottom]`
  at chapter **end** (sticky physics: a bottom-parked element must trail its
  scope to engage).
- Chapter length varies with `mixed`, because equal-size chapters hide
  parking/push bugs (every wagon behaves identically).
- Trailing spacer `<div class="tail"></div>` with `height:100vh`: without it
  the last wagon can never reach the top edge and can never park — a real bug
  class that must not be confused with an engine fault.
- `data-bg` colour cycle red→blue→green→yellow→purple→checker; `R<br>` runs
  use the same letter as the colour so text and image are matched by eye.

## Visuals (no external URLs)

- `linear-gradient()` / `radial-gradient()` strings for `cover`/`contain`.
- `svgURI(w,h,label)` → `url('data:image/svg+xml,…')` with explicit
  `width`/`height` attributes, a 1px border, a checker band and the wagon
  index at each corner — so scaling, offset and edge contact are all visible.
  Encoding is `encodeURIComponent` (a raw `#` in a fill colour truncates the
  URI). Build the *bare* URI in the shared helper and let each call site wrap
  it in `url('…')`: a generated value must never contain the quote character
  that closes its own attribute.
- Every visual must have a synchronous, known size. Nothing may depend on
  image load timing.
- `background-size` is always its own declaration. Never
  `background-image:<gradient> 50%/72px` — position/size after an image belong
  to the `background` shorthand only, so the whole declaration would be
  dropped and the box silently transparent.

## Diagnostics overlay (`#diag`)

The panels are `position:fixed` only on wide viewports; below 1100 px they go
static and full-width, *in flow above `#app`*. In that regime every panel
height change shifts `#app` — and therefore every anchor — so the harness
records the combined panel height after painting and calls
`Snowfall.refresh()` exactly when it changes, never per tick. An idle page
must stay idle.

Updated at 10 Hz, never per frame: `scrollY`, `innerHeight`, `--snow-vh`,
document height, wagon count, active wagon index, parked count, pushed count,
FPS + worst frame ms, event fire counters, and a PASS/FAIL list from the QA
probes. Reads engine state through `Snowfall.debug` — the engine publishes
those arrays so the overlay is a view, not a second model. Left rail: fixed
tick marks every 100 px of viewport + a marker at `scrollY`. Wireframe mode:
for each wagon, a dashed 1px outline at its anchor Y (where its text is) and
a solid outline at its rendered box — the difference *is* the bug report.
Wireframes use `getBoundingClientRect` and only run when enabled.

## QA probes (the mechanical part of every later plan's criteria)

QA stops autoscroll first: a page that is scrolling itself is not a
measurement surface. QA is single-flight: while a run is pending, buttons are
disabled and another key/click is ignored, because every probe shares
`scrollY`, event latches and the result rows. All are async: they drive
instant `window.scrollTo`, wait 2 rAF, read `el.style.transform` (inline value
= the engine's output verbatim, no computed-style cost). Where a probe needs
a *sampling clock* it scrolls and calls `Snowfall.step()` synchronously
instead of using `autoscroll` — an rAF animation is a human aid, not a
measurement source. Probes parse the transform numbers with a tolerant regex
rather than comparing formatted strings: engines normalize `translate3d`
spacing differently. They must also survive a DOM with no layout by reporting
`skipped` rows instead of throwing.

- `reversibility()` — walk 10 evenly spaced `scrollY` values down, then up;
  assert the transform string per wagon is byte-identical for equal `scrollY`,
  and that each scroll request actually landed where it was sent (±1 px):
  drift means layout shifted under scroll and scroll anchoring rewrote
  `scrollY` — an engine-input failure the transform diff alone reports only
  as "N differ".
- `overlap()` — at each of 10 positions assert `y[i]+h[i] <= y[i+1]+1` for
  consecutive wagons whose `data-dir` is `top` (lateral/bottom exits exempt).
- `anchorAlign()` — for each wagon whose cushion (gap to next − own height)
  is ≥ 0, scroll so `free == 0` and assert rendered `y == 0` (±1 px), and at
  `free == 300` assert `y == 300` (±1 px). Every settle re-fetches the wagon
  record and re-derives its targets from it: the record is a fresh object
  after each re-measure, and a `refresh()` consumed mid-run (resize,
  `fonts.ready`, a panel height change) must not let the probe compare two
  geometries.
- `jump()` — walk `scrollY` in fixed px steps; legal `Δpos` is `-step`
  (riding), `0` (parked), or anything in `(-step, 0)` (the one frame a wagon
  parks or starts being pushed). `|Δ| > step` or `Δ > 0` is a jump — except
  `data-dir=bottom` wagons, which travel down while pushed: their bound is
  mirrored to `Δ ∈ [−step−1, +step+1]`.
- `stickSlots()` — with `stick=both`: at mid-chapter assert the top caption's
  box top is `0 ±1` and the bottom tag's box bottom is `vh ±1`; assert both
  paint above the parked wagon (elementFromPoint at their centres hits the
  stick element, not the wagon).
- `events()` — `refresh()` at the top so earlier probes do not consume
  latches; slow full pass *including the document end*: assert per chapter
  `view→center→parked→end` with count 1 each and no `skip`; then `refresh()`
  at the top again and `scrollTo(bottom)` in one flick: assert `skip` fired
  and `view` did not for chapters fully jumped.

Each probe appends `{name, ok, detail}` and logs
`console.info('Snowfall QA', …)`. Harness installs
`window.Snowlog = msg => (log.push(msg), …)` and event scripts call it, so
the panel can count fires without touching `console`.

## Acceptance criteria

- [ ] Opening `index.html` by `file://` shows controls and generated story,
  no console errors, zero network requests (verify in devtools Network tab).
- [ ] Changing any control and pressing `regen` rebuilds 12 chapters in
  <100 ms and resets `scrollY` to 0.
- [ ] With the engine script removed the page still renders readable prose
  with in-flow background blocks — the no-engine baseline is visibly
  different from a broken engine. With JS disabled entirely the same fallback
  applies.
- [ ] Every chapter label, line number and colour run is distinguishable;
  you can state `scrollY` ±50 px by reading text alone.
- [ ] `view-source` contains no external URLs: all visuals are gradients or
  `data:image/svg+xml`.
- [ ] Same hash ⇒ identical DOM (byte-compare `#app.innerHTML` after two
  regens with the same hash) so a bug report is just the hash.
- [ ] `reversibility`, `overlap`, `anchorAlign`, `jump`, `stickSlots` all run
  from the panel and print PASS/FAIL. With no engine they trivially pass
  (nothing moves); with 0.2 they must pass for real — that is 0.2's gate.

## Pitfalls

- Determinism over realism: seeded PRNG, no `Math.random`, no `Date` in
  output.
- Do not put `overflow:hidden|scroll|auto` on `#app` ancestors — see overview
  Layout Contract; it silently traps `sticky` and kills 0.2. Horizontal
  safety is `overflow-x:clip`.
- `harness.css` must not set `background` on `#app` (covers wagons).
  Page colour goes on `html` — 0.3 drives it.
- Keep `#gen`/`#diag` outside `#app`: the engine collects from `#app`, and
  the fixed panels must not be measured as anchors.
- Do not scroll with `behavior:'smooth'` inside QA probes — it never settles
  and falsifies results. Use instant `scrollTo` + 2 rAF.
- Prove every gate fails before trusting it green: break one thing on purpose
  and re-run. A suite whose assertion is vacuous is worse than no suite.
