# 0.3 — Style / Theme Morph Engine

## Goal

Page theme (background colour, text colour, class-driven look of page, menu
and vignette) morphs smoothly between scroll anchors — like a sunset or
opening a door onto a bright room: continuous, interactive, reversible, never
a blink. Author marks anchors declaratively; no per-chapter JS.

## Non-goals

- Not a CSS-in-JS framework, no shader, no per-pixel work.
- No timeline editor: anchors are just attributes on elements.
- Does not animate `background-image`, `box-shadow` blur, or any property
  whose transition repaints the whole text layer per frame.

## DOM contract

```html
<section data-bg="#0b1020" data-fg="#e8e6e1" data-style="night">
<div class="snow-bg" data-bg="#ffe8a0" data-style="sunset" data-range="180">
<p data-style="compact">text</p>
```

- `data-bg` — page colour (`#rgb`, `#rrggbb`, `#rrggbbaa`, `rgb()`/`rgba()`,
  `%` components), or any CSS paint value that does not parse as a colour.
- `data-fg` — text colour, same grammar.
- `data-style` — space-separated class names applied to `<html>`.
- `data-range="PX"` — how many px *before* this anchor the morph runs, i.e.
  the morph **completes at the anchor** and then holds. Default
  `min(interval, --snow-vh * 0.6)`.
- Free placement: collected by
  `querySelectorAll('[data-bg],[data-fg],[data-style]')` in document order,
  never by section traversal. A style anchor may be the same element as a
  wagon (`.snow-bg` with both `background-image` and `data-bg`).

Author CSS provides the look; the engine only writes variables and names
classes:

```css
html{background:var(--snow-bg,#fff);color:var(--snow-fg,#111)}
html.fog #app{filter:contrast(.94) saturate(.8)}
html.night .n{outline:2px solid #6cf}
```

## Architecture

Second `Snowfall.use()` subscriber. No scroll listener of its own, no
measurement in `frame()`: it uses `Snowfall.anchorY(el)` from the shared
pass, so a `.snow-bg` style anchor gets the wagon's marker (its own rect is
transformed and would be wrong). State, one flat typed array per channel set,
all preallocated at `measure`: `ay[]`, `br/bg/bb[]`, `fr/fg_/fb[]` +
`hasBg[]/hasFg[]` presence bytes, `range[]`, and `cls[]` (plain array of
strings, only read at class swap).

## Per frame

```js
const c = scrollY + vh * 0.5;              // the reading line — ONE reference
const i = lastIndexLE(ay, c);              // -1 → before first anchor
if (i >= n - 1) { t = 1; j = n - 1; } else { j = i + 1;
	t = ease(clamp((c - (ay[j] - range[j])) / range[j], 0, 1)); }
// hold previous colour when an anchor omits a channel
if (hasBg[j]) col = mix(colorOf(i), colorOf(j), t) else col = colorOf(i);
setVar('--snow-bg', col); setVar('--snow-fg', col2); setVar('--snow-t', t);
```

- Everything — segment choice, lerp, class swap — uses the same `c`. Mixing
  a centre-based index with a raw-`scrollY` progress leaves `t` unable to
  reach 1 before the segment ends → colour **snaps** at every anchor. Morph
  completing *at* `ay[j]` makes `t==1` coincide exactly with the class swap
  and with holding, so no discontinuity is possible.
- `i < 0` → fully hold anchor 0; `i == n-1` → fully hold the last anchor.
- `ease(t) = t<.5 ? 2t² : 1-(2-2t)²/2` (easeInOutQuad): cheap, no harsh start.
- Colour mixing is done in linear light with two lookup tables
  (`srgbToLinear`, `linearToSrgb`) built once at load; sRGB-space lerp visibly
  darkens mid-transition (the "muddy purple" between blue and red).
- Writes are quantised: keep `lastBg/lastFg` ints, `setProperty` only when
  the 8-bit value changed. Steady state = zero string concat, zero style
  dirtying. `--snow-t` is quantised at 1/64 so authors may key off it without
  invalidating styles every pixel.

## Classes

- The engine owns a class list on `<html>`: it records the names it added,
  removes exactly those, adds the current segment's. Author classes elsewhere
  are untouched.
- One segment wins: `data-style` on the last passed anchor replaces the
  engine set. To keep a class for several chapters, re-state it. This is
  deliberate: "one active at a time" is only implementable if the model is
  *segment → set*, and it stays fully reversible without a stack.
- Swap exactly when `c >= ay[j]` (`t` reaches 1), so class change and colour
  arrival are the same instant.
- **No `transition` on `--snow-bg`/`--snow-fg`/`background-color`**: the lerp
  is the smoothing; a CSS transition on top adds lag, fights the per-frame
  write, and makes reversibility time-dependent. Transition only class-driven
  props (`filter`, `opacity`), and only if the author wants it.

## Interaction with wagons

- Wagons paint in flow behind later text; the page colour lives on `html`
  (never `#app`, which would cover shorter wagons). A `cover` wagon hides the
  page colour while parked — that is correct layering, and `fixed`/`auto`
  wagons let the morphing colour show around them.
- Style lerp continues while a wagon holds at the edge, so "cold→warm while
  the picture stays" works with no coupling between the two controllers.
- Class-driven `filter` on `#app` is a full-layer raster per change — note
  the cost; prefer it on small chrome (menu, vignette), not on scrolling
  text.

## Test matrix (extends 0.1 harness, `style=on`)

- Colour cycle red→blue→green per chapter, slow scroll: glide, no step.
- `data-range="80"` vs `"800"`: quick settle vs whole-chapter glide.
- Free-placed `data-bg` between two text lines (no section): still lerps at
  its own Y; the section's own anchor keeps holding before it.
- Anchor with only `data-fg` (no `data-bg`): colour holds previous, no flash
  to default.
- `cover` wagon + `data-bg` on the same element: both apply, no double
  transform.
- Reverse scroll: colours retrace exactly (QA `reversibility()` extended to
  read `getComputedStyle(html).backgroundColor` at the same 10 positions).
- `wagons=0`: morph still runs from `core` alone (standalone check).
- Regen with an extra anchor: `refresh()` picks it up, no reload.

## Acceptance criteria

- [x] Between two anchors, `--snow-bg` moves monotonically and reaches the
  target colour exactly at the anchor; no sample position shows a step > 1/255
  per frame at 60 fps.
- [x] No colour snap at any anchor crossing (verify `c = ay[j]-1` vs `ay[j]`
  differ by ≤ `1/range` of the gradient).
- [x] `data-style` class becomes active at `c >= ay[j]` ±2 px, previous engine
  classes removed; engine never removes a class it did not add.
- [x] Zero layout shift from style change (only paint: colour, filter,
  opacity).
- [x] Works with wagons on and off; works when no `.snow-bg` exists at all.
- [x] `reversibility()` passes on computed colours.
- [x] Idle cost is zero: no `setProperty` calls while `scrollY` is unchanged.

## Pitfalls

- Do not animate `background-image`; do not lerp gradients. A non-colour
  `data-bg` value is assigned verbatim at the boundary (instant, class-like) —
  documented, because gradient interpolation would need a stop table.
- Do not read `getComputedStyle` per frame (forced style recalc) — the engine
  compares against its own last-written integers.
- Guard missing anchors: `hasBg[i]` false → hold, never mix with `NaN`
  (`NaN` in a custom prop silently kills the whole theme, which is nasty to
  debug).
- `data-range` shorter than 1 px must clamp to 1, not divide by zero.
- Collect via attribute selector in document order; section traversal
  silently drops free-floating anchors, which is the feature.
- Run the spec's colour snippets: hex nibble `c > 9 ? c-0x37 : c-0x30` and
  `rgb()` `%` handling are the classic invisible-in-review parse bugs. Alpha
  is the only 0-1 channel in CSS colours; components are 0-255 with `%`
  support.

## Implementation notes (as built, 2026-09-17)

- `chanAt` target search skips `kind-0` anchors (no channel info ⇒ must not
  disturb a running morph); per-channel effective zone starts `sbg[]/sfg[]`
  are pre-clamped to the previous value anchor, so zones never overlap and
  `t` always runs 0→1 exactly. An explicit `data-range` longer than the
  interval compresses to the interval instead of snapping mid-morph.
- `L2S` is 4096 entries, not 256: a 256-entry linear table quantises the
  dark end to ±6 sRGB steps. Round-trip sRGB→linear→sRGB must be exact for
  all 256 inputs (verified in node).
- Default range uses JS `innerHeight` — the same value the engine writes to
  `--snow-vh`, without a computed-style read.
- `qMorph` samples arrival 1px *past* the anchor: integer `scrollY` cannot
  hit a fractional `ay`, and from above the hold is bit-exact. Snap bound
  is `ceil(4Δ/D)+1` (true Δc ≤ 2 from ±0.5px landing on each sample × ease
  slope ≤ 2/D, +1 quantisation). Class swap checked at ±2px; a foreign root
  class must survive; anchors' own style/class must be untouched; idle 350ms
  must show zero `setProperty`; regen adds + removes an anchor via refresh.
- `inst.morph` record: `n/els/ay/range/bgKind/fgKind/cls` + colour arrays
  `br/bg_/bb/ba`, `fr/fg_/fb/fa` + `tokBg/tokFg` + effective starts
  `sbg/sfg`. Teardown runs `sub.off?.()` in reverse order (`wagonsOff`,
  `styleOff`) from `setEnabled` and `destroy`.
- Harness: flat chapters carry anchors on zero-size `<i class="snow-fg">`
  (same rng draws as the section branch, in the same order); every 3rd
  wagon anchor is fg-only (counter-based, no layout change);
  `reversibility()` extended to computed `<html>` colours + root classes;
  `qStickSlots` encodes the true sticky rule (min/max of flow position,
  viewport slot, and parent content-box constraint incl. margins).
- 0.2-followup fixes landed with 0.3 (needed for a green matrix at vh 900):
  `stickyShown` `ext>=pH` shortcut deleted (was pure bug, misplaced tall
  wagons by `−free`); `qStickSlots` true-rule (probe expected viewport park
  where the section constraint or a maxY scroll clamp legitimately wins).
- Matrix: 8 configs + wagons0 + noengine + token-anchor check, all green at
  1280×900; seed sweep (5 base + 9 tight across nest modes) all green.
