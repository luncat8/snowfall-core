# 0.2 — Wagon Engine + Shared Core

## Goal

Every `.snow-bg` behaves as a train wagon tied to its DOM text position:
rides 1:1 with scroll, parks at the viewport edge when it arrives, stays
parked until the next wagon below collides with its bottom and pushes it out.
No overlap, no jumps, fully reversible on reverse scroll, in any size mode,
at any DOM depth, with free-placed parked text slots alongside. This plan also
lands `core`: one synchronous scroll handler, one anchor-measurement pass,
`refresh()`, and the subscriber API that 0.3/0.4 reuse.

Core idea (sticky park + JS push): parking is done by the compositor via
`position:sticky` — zero JS, zero lag. The engine computes the push chain as
pure `scrollY` math and writes only the *delta* between chain-desired and
sticky-shown positions via `transform`. When a wagon simply rides or sits
parked, the delta is 0 and nothing is written.

## Non-goals

- No parallax: a wagon never moves faster or slower than its own text, except
  the lateral exit of `data-dir`, which is a different axis.
- No section tree: wagons are one global list in document order. A wagon is
  not owned by, clipped to, or sized by its `<section>`.
- No image-decode probing: wagon box size is CSS/`data-size`, never natural
  image size — this removes a whole class of scroll glitch.

## DOM contract

```html
<div class="snow-bg" style="background-image:url('a.png')"
	data-mode="cover|tiled|contain|fixed|auto"   data-size="512" | "1024x768"
	data-w="360" data-h="220"                    data-dir="top|left|right|bottom"
	data-gap="0|100vh|240px"                     data-static></div>

<div class="snow-stick" data-park="top|bottom|top:64px|bottom:2rem">caption</div>

<section><h4>1</h4><div class="snow-bg" …></div>free text<div class="snow-bg"></div></section>
```

- `data-mode` default `cover`. `data-dir` default `top` and names the wagon's
  *own exit* direction (how *this* picture leaves when pushed — the pusher
  never dictates it). `data-static` = engine ignores the element entirely
  (escape hatch, and the only supported "off").
- `data-size` sets the element box (`WxH`, or `W` square). Required for
  `auto`, optional for `fixed` (default 512). `data-w`/`data-h` are accepted
  as separate-attribute aliases when `data-size` is omitted.
- `data-gap` (default `0`) = flow footprint the wagon keeps. `0` means the
  wagon overlays: following text starts at the wagon's top edge and scrolls
  over the parked picture. `100vh` keeps a full screen of flow space (a pure
  image beat). The engine implements it as
  `margin-bottom: calc(gap − height)`.
- `.snow-stick` with `data-park` parks authored text at a fixed viewport slot:
  `top` (offset default `0`) or `bottom` (offset default `0`), with optional
  `:offset`. Top-parked sticks belong at the **start** of their scope,
  bottom-parked at the **end** (sticky physics: a bottom stick must trail its
  scope to engage). Sticks paint above wagons (`z-index:5`).
- `.snow-window` is by contract an **in-flow** background block that never
  parks — the "just a normal background" case. It is not an alias of
  `.snow-bg`; treating them alike would remove the author's only way to say
  "no wagon".

The engine injects its own `<style id="snowfall-core-css">` once (works in
any host page, single-file friendly):

```css
.snow-bg{position:sticky;top:0;pointer-events:none;background-repeat:no-repeat;background-position:center}
.snow-stick{position:sticky;z-index:5}
.snow-a{position:absolute;width:0;height:0;margin:0;padding:0;border:0;overflow:hidden;visibility:hidden;pointer-events:none}
```

Stick offsets are applied as the `top`/`bottom` sticky value from `data-park`
at collect time (pure CSS from then on — sticks need no per-frame JS).

## Core

- One passive `scroll` listener runs `frame()` **synchronously** (no rAF
  coalescing: a coalesced push frame lags a fast flick by a frame, which
  reads as a glitch). `frame()` reads `scrollY`/`innerWidth`/`innerHeight`
  only, runs every subscriber's `frame`, write-gated. An idle page runs
  nothing — idleness is structural, not scheduled.
- `resize`/`orientationchange` and `document.fonts.ready` call `refresh()`
  (rAF-coalesced): re-collect, re-measure, one frame.
- Passes are strictly separated: `measure()` may read layout (markers,
  `offsetHeight`); `frame()` writes `transform`/custom props only.
- `measure` order = registration order: wagons first (they create the markers
  that style/event anchors reuse), then morph, then events.
- `VNS`-style `use({measure, frame})`, `refresh()`, `step()`, `anchorY(el)`,
  `setEnabled(bool)`, `destroy()`, `onFrame` hook. `step()` runs one manual
  frame — tests and QA probes drive this instead of animations.

## Anchor measurement

`offsetTop` is **wrong** here (it is `offsetParent`-relative, and a
positioned ancestor changes the origin). Contract instead:

- Engine inserts `<i class="snow-a">` immediately **before** each wagon:
  zero-size abspos contributes nothing to any line box or scroll height, so
  inserting it never shifts the text.
- `Y = marker.getBoundingClientRect().top + scrollY`, all markers read in one
  loop after all DOM writes, so at most one forced layout per refresh.
- `el.__snowA` caches the marker, `el.__snowStamp` dedupes within one
  refresh; `refresh()` wipes the anchor table and re-creates indices (O(N)).
- Per wagon also measure `ext[i] = offsetHeight` and the parent box
  (`parentTopDoc[i]`, `parentBottomDoc[i]` from the parent's rect + scrollY):
  CSS sticky constrains a wagon to its parent, and the engine must mirror
  that — see Park mirror below.

## Park mirror + chain math (the whole engine)

Preallocated arrays of length `N`: `y[N]` (anchor), `ext[N]` (box height),
`free[N]`, `park[N]`, `pos[N]`, `dir[N]`, `lastX[N]`, `lastY[N]`.

CSS `position:sticky;top:0` shows, without any transform:

```js
stickyShown = min(max(free, 0), parentBottom - ext)   // parent-aware clamp
if (ext >= parentH) stickyShown = free                 // taller than parent: sticky never engages
```

The engine mirrors that formula in pure math (`free[i] = y[i] - scrollY`,
`parentBottom[i] = parentBottomDoc[i] - scrollY`), then runs the 1D chain
over the *desired* positions and writes only the delta:

```js
// desired: ride with text, park at the edge, never overlap the wagon below.
// pos[i] = min(park[i], pos[i+1] - ext[i])   — sweep i = N-1..0
park[i] = stickyMirror(i) extended: max(free[i], 0)   // hold even past parent end
pos[N-1] = park[N-1]
for (let i = n - 2; i >= 0; i--) {
	const ceil = pos[i + 1] - ext[i];                  // contact with wagon i+1
	pos[i] = ceil < park[i] ? ceil : park[i];
}
// write only what sticky did not already show:
dy[i] = pos[i] - stickyShown[i]
```

Why this shape:

- `min(park, ceil)` is a min of continuous functions, so it is continuous
  and monotone in `scrollY` (no jump, no hysteresis needed) and it is a
  *ceiling* — a wagon is never pushed below or past its own anchor. Gating
  the push on "only when parked" instead would keep alignment but produce a
  `H−gap` pixel **jump** at the parking frame for tight chapters.
- In the common case the delta is exactly `0` (riding: `pos == free ==
  stickyShown`; parked: `pos == 0 == stickyShown`) so write gating skips the
  DOM entirely — the compositor did the work.
- When the parent ends before the next wagon arrives, CSS would drag the
  wagon up early; the delta turns positive and *holds* it parked (sticky-range
  extension). The hold offset moves 1:1 with scroll and the handler is
  synchronous, so it stays smooth.
- Push must use the already-resolved `pos[i+1]`, not `free[i+1]`, or a chain
  of 3+ wagons pushes incorrectly (only the last gap is respected).
- Coupling is the accepted cost: every cushion (`gapNext − ext`) below wagon
  i ≥ 0 ⇒ wagon i rides exactly on its text, parks at `y=0`, waits. Some
  cushion < 0 ⇒ wagons are already in contact while riding; they form a
  continuous filmstrip and the upper one exits as soon as the lower one
  arrives. That is the wagon metaphor, not a bug — and it is why `anchorAlign`
  QA only asserts alignment where every cushion is ≥ 0.
- Nothing pushes the last wagon: it parks at 0 and holds until document end.

## Exit vectors (applied after the chain, still a pure function of `pos[i]`)

`d = park[i] − pos[i]` (push depth, ≥ 0). `data-dir` is the wagon's own exit:

```js
top:    x = 0,  y = pos[i]              // slides up out of view (default)
left:   x = -f·vw, y = park[i]          // parks at top, then pushed sideways
right:  x = +f·vw, y = park[i]
bottom: x = 0,  y = park[i] + d         // pushed down across the screen
```

`f = d / ext[i]`: when the next wagon has fully replaced this one
(`d == ext[i]`) the box is just past the viewport edge. Further chain push
keeps going, already off-screen. Writing lateral `x = d` 1:1 would slide a
256px box only 256px — it would sit mid-page with every later wagon nudging
it, which reads as "it never leaves".

`left`/`right` keep `y = park[i]`, i.e. they park at the edge and stay there
vertically, so a lateral exit never overlaps the wagon below it on the Y
axis; `bottom` deliberately crosses the screen (author asks for it), so
`overlap()` QA skips non-`top` wagons. The chain itself stays 1D — the exit
projection must never feed back into `pos[]`, or a bottom exit un-pushes the
wagon above it (a real bug observed in a 2D-coupled prototype).

## Writes

```js
for (let i = 0; i < n; i++) {
	// …exit vector…
	if (x === lastX[i] && y === lastY[i]) continue;   // parked → zero work
	el.style.transform = 'translate3d(' + x + 'px,' + y + 'px,0)';
	lastX[i] = x; lastY[i] = y;
}
```

Quantised-to-integer pixels are not wanted (sub-pixel translate keeps motion
smooth); instead skip writes when the value is unchanged. `will-change:
transform` per wagon is set at collect time. Culling: a wagon fully above
(`y + ext <= 0`) or fully below (`y >= vh`) keeps its last transform — no
`display`/`visibility` toggles, which would force style recalc and risk pops
on reverse scroll.

## Size modes (box + paint, mapped by attribute)

| mode | box | background |
|---|---|---|
| `cover` | `100% × var(--snow-vh)` | `cover`, centred |
| `tiled` | `100% × var(--snow-vh)` | `auto`, `repeat` (image tiles at native size; use an image, not a gradient) |
| `contain` | `100% × var(--snow-vh)` | `contain`, centred |
| `fixed` | `data-size`/`data-w`/`data-h` px, default 512 | `100% 100%` (art stretched into box) |
| `auto` | `data-size`/`data-w`/`data-h` px | `auto` (art unscaled, top-left) |

Engine sets `--snow-vh/--snow-vw` from `innerHeight/innerWidth` on the root,
so mobile URL-bar resize does not make every `cover` wagon taller than the
screen (the classic 100vh bug), and publishes `--snow-w/--snow-h` per wagon
for authored CSS. `ext[i]` uses the element box height even for `contain`,
whose visible art is smaller: the chain is about *boxes*, so a `contain`
wagon still blocks the wagon below over its full box. A wagon shorter than
the viewport intentionally leaves a band of page colour below it — that is
the point of `fixed`/`auto`.

## Test matrix (extends 0.1 harness)

- `gap=mixed`, `mode=mixed`, `dir=mixed`, `flow=mixed`: slow/fast/reverse
  scroll — no jumps, no overlaps, byte-identical transforms per `scrollY`.
- `tight` preset: wagons already in contact — filmstrip behaviour, upper
  exits as lower arrives, no jump at the parking frame.
- `fixed` 256px wagon between two `cover` wagons: short box parks, shows page
  colour band, gets pushed correctly.
- `data-dir=left/right`: parks at top, exits sideways exactly to the edge.
- `data-dir=bottom`: crosses the screen; wagon above keeps leaving (no
  jump-back).
- Wagon inside a short `<section>` that ends before the next wagon arrives:
  hold keeps it parked (sticky-range extension).
- `nest=flat` vs `section`: identical wagon behaviour.
- `stick=both`: captions hold top, location tags hold bottom, both paint
  above the parked wagon; neighbouring chapter's sticks replace them.
- `data-static` wagon and `.snow-window`: never move, never join the chain.
- Document ends before last wagon can park (no `.tail`): engine must not
  fake a park; with `.tail` it must park cleanly.

## Acceptance criteria

- [ ] `reversibility()` passes: byte-identical transforms for equal `scrollY`
  going down and up, at 10 positions, all modes.
- [ ] `overlap()` passes for `data-dir=top` wagons at all sampled positions.
- [ ] `anchorAlign()` passes: while riding, wagon top == its marker line ±1
  px; once parked, `y == 0` until contact; ±1 px at the contact frame.
- [ ] `jump()` passes: per-frame `|Δtransform − ΔscrollY| ≤ 1` px while
  riding, `Δtransform == 0` while parked. `data-dir=bottom` wagons travel
  *down* while pushed, so their bound is mirrored: `Δy ∈ [−step−1, +step+1]`
  (down at most scroll speed, up at most scroll speed).
- [ ] `stickSlots()` passes: top/bottom sticks hold their slots and paint
  above wagons.
- [ ] Last wagon parks and holds at `top:0` to the bottom of the document
  (nothing pushes it).
- [ ] `frame()` allocates nothing and reads no layout: verified by code
  review + `Snowfall.debug.writes == 0` while idle.
- [ ] All five modes interleaved, `file://`, no network, no image-decode
  dependency.

## Pitfalls

- Never set `top`/`left`/`margin` in `frame()` — only `transform` (plus
  `gap`-derived margin at collect/resize). Writing layout properties
  invalidates the anchors you measured → drift → "wagon crawls".
- Do not read `getBoundingClientRect` of the **wagon** for its anchor: it is
  transformed. Read the marker.
- Do not tie a wagon to `<section>` bounds for order, size, or lifetime.
- Push must use the already-resolved `pos[i+1]`, not `free[i+1]`.
- Measuring `Y` inside `frame()` (no markers) → self-referential drift.
- `overflow:hidden|scroll|auto` on any wagon ancestor silently traps `sticky`
  — use `overflow-x:clip`. This is the #1 way the engine "randomly" breaks in
  real markup.
- Culling with `display:none`/`visibility` pops on reverse scroll and forces
  style recalc — leave off-screen wagons transformed, never toggle.
- Keep `#gen`/`#diag` out of `#app`, else they get collected as anchors.

## Open decisions (resolved, keep as-is)

- Size source of truth is `data-mode` + CSS mapping; computed
  `background-size` is never parsed. `auto` means "author-provided size", not
  "natural image size" — chosen deliberately so a `file://` page with SVG
  data URIs needs zero async measurement.
- `data-dir` names the wagon's *own exit* direction, not the pusher's action.
- Parking is compositor-side (`sticky`); the engine writes push/hold deltas
  only. A fully JS-positioned layer was rejected after review: it re-adds the
  exact fast-scroll lag the sticky approach eliminates.
