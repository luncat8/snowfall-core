# 0.5.5 demo report — HD-region cover pages (archived)

Two standalone pages (`region-cover-1.html`, `region-cover-2.html`) render the
region adapter on real pixels from `file://`: they generate their own art, so a
double-click is a test.

**`region-cover-1.html` — one background, `data-mode="cover"`**
The image pair is color-coded for the eye: the base is a *blurred* coordinate grid (labels every 200px) with a dashed red region outline; the HD crop is the *sharp* twin of exactly that rect, 1:1 with it (the material rule), drawn in the base's coordinate space. Correct layout = sharp grid continues the blurred grid with zero offset, red frame lying on the dashed outline. Verified parked @1440×900, 12/12 checks PASS:
- crop **1350×900 @ (45,0)** — the max possible size with aspect kept (`s = min(1440/900, 900/600) = 1.5`), touching the window on its limiting axis, never cover-cropped;
- blurred outpainted base **2400×1500** covering all the rest;
- crop exactly on its region of the base; painted rects == HD-region reference math at 1e-9.

**`region-cover-2.html` — two backgrounds**
`auto-check both` parks #1 (same scene as page 1, verified identical), snapshots it, then parks #2: #2's crop **1440×810 @ (0,45)** (touches the width axis, all reference rows pass) while #1's children stay **byte-identical** (`1350px|900px|translate(45px,0px)`) and the wagon is pushed rigidly off-screen (dy = −900) — proper size preserved. Screenshots of both parked states confirmed the alignment by eye (the PNGs were workspace scratch, not committed). Resize also re-fits correctly (portrait 390×844 re-verified); the only case where the base can't cover is a very portrait window, where the reference itself centres the picture — both implementations agree.

**On "bugs not fixed":** the math matches the live HD-region repo at 1e-9 (node parity + 44 rendered checks, 5 gates green). What *was* a real page-level bug — fixed in the same round — is the **head-load crash**: loading the scripts from `<head>` threw in the adapter before its API/HUD/gestures were installed, so such pages painted crops but had no API, no HUD and no zoom/pan. That is gated now (fake-DOM + `scene1-head.html`), and the rendered gate covers exactly the two scenarios above (`test/browser/scene1.html`, `scene2.html`). The panel prints expected-vs-painted numbers per row, so a misplacement shows as a red row with both numbers.
