# 0.5.1 — Source Editor · Two-Way Sync

## Goal

The read-only output field of 0.5.0 becomes an editable source pane and the
harness becomes a split editor: source text ↔ live preview. Typing applies
source to the preview; inspector edits and `+ chapter`/`+ background`
serialize the preview back to source; scrolling either side brings the other
to the same chapter. The round-trip is stable: canonical text parses to a
DOM that serializes to the same text. Copying the result is then just
selecting the pane — the copy button stays for one-click export.

## Layout — a split with no scroll container

- The preview stays the document itself (`#app` + page scroll). The split is
  made of fixed panels around it — never an iframe or an overflow pane:
  `overflow:hidden|scroll|auto` on any wagon ancestor traps
  `position:sticky` and silently kills parking. Moving `#app` into a pane is
  the tempting wrong move; it is forbidden.
- `source (s)` toggles the pane. On wide screens the left fixed column
  switches to a full-height source pane (panel controls collapse into a thin
  toolbar above it, plus a `sync scroll` checkbox, default on) and the
  body's left padding widens so `#app` remains visible beside it. Below
  1100px the pane stacks above the story, static and collapsible.
- The pane is one `<textarea id="src">`: monospace, `spellcheck=false`,
  `wrap="off"` (soft wrap would break line↔pixel arithmetic), fixed
  line-height from CSS, Tab key inserts a tab, undo/redo native. A status
  line reports `applied · 6 chapters · 9 backgrounds` or a warning.

## Sync model

One DOM, one canonical text (the 0.5.0 serializer), two write paths.

**Preview → source.** Every editor DOM mutation (regen, add, inspector
apply) re-serializes into the pane — except while the pane is focused and
dirty: never clobber typing. If a DOM-side edit arrives while dirty, flush
first: apply the pending source, then perform the edit.

**Source → preview.** Debounced 400 ms after the last keystroke, immediate
on Ctrl+Enter:

1. Parse via a detached `<div>` + `innerHTML`. `type="txt"` script blocks
   stay inert — `innerHTML` never executes scripts, which is exactly the
   engine's safety property.
2. Tag-balance check: count opens vs closes per tag name; unequal ⇒ status
   warning (`<section> closed by parser`), and apply the parser-healed DOM
   anyway — the browser's fix is the result, blocking helps nobody.
3. Swap: replace the children of `#app` except `.tail`.
4. `Snowfall.refresh()` — the default pre-fill keeps already-passed anchors
   from re-firing events. Never `refresh(true)` here: that variant exists
   for QA probes that want the re-fire.
5. Restore the reading position: before the swap capture the chapter ordinal
   at the reading line plus the px offset from its heading anchor; after
   measure scroll to the same ordinal's new anchor + offset, clamped to
   `maxY` (raw `scrollY` is wrong — the document height changed). No
   chapters in the source ⇒ clamp `scrollY`.
6. Store the canonical text as the `lastApplied` snapshot.

**No caret jumps.** Applying from source leaves the user's text untouched;
normalization to canonical form happens on blur (or on any DOM-side action
while the pane is clean). While dirty, the status shows `source ≠ preview`.
`Esc` while focused reverts the pane to `lastApplied`.

**Round-trip invariant.** `serialize(parse(t)) == t` for any canonical `t` —
the serializer emits tab-indented one-element-per-line text in DOM attribute
order, and `innerHTML` preserves that order. QA asserts: apply the pane text
twice ⇒ byte-identical serialization, zero visible change.

**Empty source** is valid: the preview keeps only `.tail`; regen and the add
buttons still work on the empty state.

## Sync scroll

The two panes track each other's reading position at **chapter granularity**
— never per-pixel (a source line has no fixed preview height), never caret
sync.

**Mapping.** A chapter is its `<h4 class="n">` line — one heading per
chapter is the 0.5.0 contract. `headingLine[i]` is built by scanning pane
lines for the heading marker, on demand and only when the chapter ordinal
changes (a few times per scroll gesture, never per frame). The scan works on
dirty text too, so sync never depends on a pending apply. While dirty,
source ordinals clamp to the chapters the preview currently has.

**Preview → source.** When the 10 Hz tick sees the reading-line chapter
change and the pane is unfocused, scroll the pane so the chapter's heading
line sits ~25% down: `scrollTop = headingLine[i] * lineH − paneH/4`,
clamped. Focus and selection are never touched — the pane never steals the
caret.

**Source → preview.** On textarea scroll, map the top visible line
(`scrollTop / lineH`) to the last heading at or above it; if that ordinal
differs from the preview's reading-line chapter, scroll the preview so the
chapter heading lands near the top (`anchorY − vh*0.1`, clamped, instant
`scrollTo` — smooth scroll would fight the very scroll events driving it).

**Loop prevention — driver/follower.** The side that last received a
*manual* scroll gesture (wheel/touch/keyboard/drag) is the driver for
600 ms, renewed per event; programmatic scrolls never promote a side. Follow
writes are allowed only when the *other* side is not the driver, so a
follow echo dies inside the window instead of ping-ponging. One more guard:
after a programmatic `scrollTop` write the textarea's asynchronous scroll
events are ignored for 300 ms.

**Pauses.** Pane focused ⇒ preview→source paused (typing owns the pane's
viewport). `sync scroll` off ⇒ both directions off. `qaBusy` ⇒ sync fully
paused (probes own the preview and need deterministic geometry).

## Copy

`copy template HTML` copies the current canonical serialization — identical
to the pane content after normalization. Clipboard API + `execCommand`
fallback, unchanged from 0.5.0.

## Non-goals

- No syntax highlighting, no editor library, no vendored UI component —
  `file://`, no build, one plain textarea.
- No caret/selection sync, no per-pixel line↔prose mapping — chapter-level
  sync only.
- No custom undo stack beyond the textarea's native one; no schema
  validation beyond tag-balance warnings; no includes/multi-file stories;
  no collaborative editing; no drag-drop reordering (structure is edited as
  text — that is the feature).

## Runtime rules

- Same as 0.5.0: no modules, no network; source text never stored in the
  location hash.
- Engine absent: parse/apply/serialize still work; `refresh` is the guarded
  no-op; reading-position restore and source→preview fall back to clamped
  `scrollY` / heading `offsetTop`.

## Test matrix

- Type in the pane → preview updates within the debounce; the reading line
  stays in the same chapter at the same heading offset; `LOG` gains no
  events from anchors above the fold (pre-fill held them silent).
- Inspector edit while the pane is unfocused ⇒ the attribute appears in the
  pane immediately; applying the pane text afterwards changes nothing
  (byte-identical round-trip).
- Unclosed `<section>` or `<div>` ⇒ warning in the status line, healed DOM
  renders, QA probes still green.
- `qOverlap` / `qAnchorAlign` pass with the source pane open ⇒ parking
  intact, no scroll-container regression.
- Delete a chapter in source while parked in a later one ⇒ preview rebuilds,
  reading position lands on the preserved ordinal (or clamps when it was
  deleted).
- Ctrl+Enter applies instantly; `Esc` reverts to `lastApplied`; blur
  normalizes the text without losing content.
- Regen / `+ background` while the pane is dirty ⇒ pending source is applied
  first, nothing is lost silently.
- Scroll preview to chapter 5 ⇒ pane shows chapter 5's heading in the upper
  third, caret and focus untouched; scroll the pane to chapter 2's block ⇒
  preview parks near chapter 2's heading.
- One scroll gesture settles: follow writes ≤ 1 per driver window, no
  ping-pong (count scroll writes during a settle).
- Focused pane: preview scrolling moves nothing in the pane; `sync scroll`
  off: both sides independent; during QA probes: zero sync writes.
- QA probes running: a pending debounce must not swap the DOM mid-probe.
- `file://` double-click: edit, apply, copy — no CSP/module errors, fallback
  copy works.

## Acceptance criteria

- [ ] `source (s)` opens the split; the preview keeps page scroll and parks
  identically with the pane open (probes green).
- [ ] Typing applies to the preview within ~0.5 s, preserves the reading
  position, and never re-fires events above the fold.
- [ ] Every DOM-side action appears in the pane immediately when clean; the
  round-trip invariant holds byte-exact for canonical text.
- [ ] The user's text and caret are never rewritten mid-typing;
  normalization happens on blur; `Esc` reverts to `lastApplied`.
- [ ] Tag imbalance warns but never blocks; empty source is valid.
- [ ] Scroll sync is chapter-level, bidirectional, loop-free (driver/
  follower), paused while the pane is focused, sync is off, or QA runs; the
  pane never gains focus from sync.
- [ ] Copy button output equals the pane's canonical text.
- [ ] Works engine-absent and under `file://`.

## Pitfalls

- A scrollable source/preview split kills sticky parking — fixed panels
  around the page-scroll preview is the only legal layout (0.0 layout
  contract).
- Rewriting the pane right after applying would jump the caret and corrupt
  the textarea's undo history — normalize on blur only.
- Swap must use `refresh()`, never `refresh(true)`: the pre-fill is what
  silences above-the-fold anchors after a rebuild; QA probes keep their own
  replay refresh.
- Suspend the debounced apply while `qaBusy` — a mid-probe DOM swap corrupts
  probe geometry and latches.
- Replaced nodes take their `.snow-a` markers with them and `ensureMarker`
  recreates them at refresh; the serializer filters markers regardless, so a
  serialize between swap and refresh is still clean.
- Restore reading position from chapter ordinal + heading offset captured
  *before* the swap; raw `scrollY` is meaningless once the height changes.
- `type="txt"` must stay inert through the edit cycle — never normalize it
  to an executable type for "live" convenience.
- Sync scroll: `wrap` must stay `off` and the line-height fixed, or
  line↔pixel math drifts; never use smooth `scrollTo` while a scroll handler
  is listening; never focus the pane programmatically; programmatic scrolls
  must never promote a driver, or the two panes oscillate.
