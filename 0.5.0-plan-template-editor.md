# 0.5.0 — Template Editor

## Goal

The harness left panel is an author-facing template editor. Choose the number
of chapters and backgrounds per chapter, and/or paste background image URLs;
`regen` generates a complete Snowfall template with writeable text
placeholders around every visual. Then refine without regenerating:
`+ chapter` / `+ background` grow the template, and the inspector always
shows the properties of the **parked background** and the **chapter at the
reading line** as editable fields that write into the live preview.
`copy template HTML` produces clean markup — no engine markers, transforms,
or QA attributes — ready to paste into a real story. Pasted URLs are
assigned to generated backgrounds in order; a deterministic local gradient /
SVG fallback keeps the tool fully usable with zero URLs and zero network.

## Non-goals

- No prose editing in the preview: placeholders are replaced in the copied
  markup (the editable source pane arrives in 0.5.1).
- No delete/reorder from the panel: any structure is expressible in the
  0.5.1 source text.
- No persistence of pasted URLs or template text in the location hash
  (panel controls only, as today).
- No second generate action: `regen (r)` is the only button-driven full
  rebuild (the URL list and fallback checkbox are generation inputs that
  rebuild on `change`).

## Workflow

1. Set `chapters` and `backgrounds`; optionally paste image URLs, one per
   line.
2. `regen (r)` builds the template — one chapter scene per chapter, one
   `.snow-bg` per background, text stubs around each visual.
3. Scroll: the inspector tracks the scene on screen; edit its properties,
   the preview and the output field update immediately.
4. `+ chapter`, `+ background` insert more — never redraw what exists.
5. `copy template HTML` (or select the output field manually) → clean
   markup for the story page.

## Controls

The tool lives in the fixed left `#gen` panel.

- `generator` fieldset: existing `preset`, `chapters` (`n` 1..12),
  `length`, `text gap`, `flow`; new `backgrounds` (`bgs` 0..4, default 1) —
  wagons generated per chapter. `bgs=0` is a valid text-only chapter.
- `wagons` fieldset: existing `mode`, `size`, `data-dir`, `nesting`,
  `sticks`, `data-bg/fg/style`, `script events` — these seed both
  generation and manual additions.
- `template` fieldset:
  - `image URLs, one per line` textarea; blank lines and lines starting with
    `#` are ignored.
  - `gradient fallback` checkbox (default on): after the pasted URLs run
    out, remaining backgrounds get deterministic local visuals
    (`linear-gradient` for cover/contain, SVG data-URI for tiled/fixed/auto,
    from the harness palette).
  - Read-only output field: the canonical serialization of the current
    template (see below), refreshed on every mutation action.
  - Status line (`ok`/`fail`).
- Button row (QA): `+ chapter`, `+ background`, `copy template HTML`
  (disabled while the template is empty). There is no second generate
  button: `regen (r)` is the only button-driven rebuild.

Rules:

- The URL list and the fallback checkbox are generation inputs, so they
  rebuild on `change` — the one exception to button-only rebuilds. Every
  rebuild is a redraw from settings + seed and discards manual edits: that
  is the "generate template" semantics. Inspector edits and additions never
  trigger a rebuild.
- Deterministic: `mixed` choices and URL assignment are a pure function of
  `SEED`. Same controls + seed + URL list ⇒ identical template.
- URL assignment is one pass in document order; after the pool runs out the
  fallback visual is used (no wrap-around reuse of the same picture).
- Pasted values are used verbatim — escaped for both the quoted CSS
  `url("…")` and the HTML attribute (`\`, `"`, quotes, newlines), never
  rewritten, never fetched by the tool itself. The gradient/SVG fallback
  adds no network request.

## Generated template

```html
<section data-bg="#2471a3" data-fg="#eaf2f8">
	<h4 class="n">2</h4>
	<p class="snow-wip">Write text here…</p>
	<div class="snow-bg" data-mode="cover" data-gap="100vh" data-source="scene.jpg"
		style="background-image:url(&quot;scene.jpg&quot;)"></div>
	<p class="snow-wip">Write text here…</p>
	<div class="snow-stick" data-park="bottom">ch2 · location tag</div>
	<script type="txt" event="view">Snowlog("ch2 view")</script>
</section>
```

- Every visual is a plain `.snow-bg`, so the existing engine owns its
  dimensions, sticky parking, `data-dir` exit, and transform. Chapters are
  top-level children of `#app` followed by the `.tail`.
- Every chapter has exactly one `<h4 class="n">` heading — the ordinal
  marker both the inspector and the 0.5.1 source sync key on.
- `snow-wip` paragraphs are the prose stubs an author replaces after copying
  (styled work-in-progress by `harness.css`, inert anywhere else).
- Flat nesting keeps the morph anchor on a zero-size
  `<i class="snow-fg" data-bg data-fg …></i>` carrier, exactly as the
  chapter generator does.
- Sticks and inert `type="txt"` event blocks follow the existing generator
  vocabulary and the `sticks`/`events` controls.

## Add

- `+ chapter` appends after the last one: heading with the next sequential
  number (appending never disturbs existing numbers), placeholders, `bgs`
  wagons, sticks/events per controls.
- `+ background` inserts a new `.snow-bg` into the currently selected
  chapter (inspector selection; else the last chapter), after its last wagon
  (or after the heading when it has none), followed by a fresh `snow-wip`
  placeholder so the new visual always has an adjacent text stub.
- Additions resolve `mixed` settings to plain defaults (`cover`, direction
  top, gap `0`, size `512`), cycle the palette, and take the next unused
  pasted URL if one remains, else the fallback visual.
- Insertion is DOM-level (detached parse + insert into `#app`), never a full
  rebuild: existing edits survive, `scrollY` is preserved. Afterwards
  `Snowfall.refresh()` re-measures, the output re-serializes, and the
  inspector selects the new element.

## Inspector — parked properties

Selection, recomputed at the existing 10 Hz diagnostics tick purely from
engine state (never own layout reads):

- Current background: the wagon with `pos[i] == 0 && free[i] <= 0` — the
  engine's parked definition; if several qualify, the last one. Overlay
  chains (`gap=0`) may never pin, so fall back to the last wagon whose
  anchor `y[i] <= scrollY + vh/2`, else wagon 0. The inspector is never
  empty. Engine absent: wagons are untransformed, so a plain rect read
  picks the wagon nearest the reading line instead.
- Current chapter: the last chapter heading (`h4.n`) whose anchor is
  `<= scrollY + vh/2` — the same reading line morph uses
  (`Snowfall.anchorY`; rect fallback for engine-absent).

Fields, applied on `change` by writing directly to the live element:

- Background: image URL (rewrites `background-image:url("…")` +
  `data-source`), `data-mode`, `data-size` (`px` or `WxH`), `data-dir`,
  `data-gap` (the engine vocabulary: number, `px`, `rem`, `vh`), and morph
  anchors `data-bg`, `data-fg`, `data-style`, `data-range` (empty value ⇒
  attribute removed).
- Chapter: the same four morph anchors, bound to the `<section>` — or to the
  `<i class="snow-fg">` carrier for flat chapters — plus top/bottom stick
  texts when the sticks exist.

Every apply runs `Snowfall.refresh()` (geometry, morph, and event anchors
are all collected at measure, so one rule covers every attribute; N is
small) and re-serializes the output. Field safety: inputs are rebuilt only
when the selected element changes; a focused control is never overwritten,
and a selection change while focused commits the pending `change` first.

## Serialize and copy

Serialize every top-level child of `#app` except `.tail`: tab-indented, one
element per line, attributes in DOM order, text content inline
(`<h4 class="n">2</h4>`). Engine/harness artifacts are dropped:

- `.snow-a` anchor markers (inserted before wagons and scripts).
- `data-snow*` attributes (QA event flags written on fire).
- Engine-owned inline styles: `transform`, `will-change`,
  `margin-top/left/right/bottom`. `width`/`height` stay — they feed the
  no-engine fallback and the engine recomputes them from `data-size`.
- `.wtag` label spans (harness decoration).

Kept: sections/headings, `.snow-bg` with all `data-*` and
`background-image`, `snow-wip` placeholders, `.snow-stick` slots, inert
`<script type="txt" event>` blocks and their bodies. Script bodies are
emitted verbatim — one-line bodies stay inline, multi-line bodies keep their
newlines at +1 indent. Free-placed non-whitespace text nodes (the engine
has no strict section syntax) are emitted as their own lines;
whitespace-only text nodes are skipped. The engine injects its own
stylesheet in any host page, so the copied markup is self-sufficient.

The output field always shows exactly this string; `copy template HTML`
copies it — Clipboard API, hidden-textarea `execCommand('copy')` fallback
for `file://`. When clipboard access is blocked the status says so and the
output stays selectable. Serialization runs on mutation actions only
(regen/add/apply/source-apply in 0.5.1), never on the 10 Hz tick — a text
selection for manual copy must not be clobbered mid-drag.

## Runtime rules

- No build step, modules, or network dependency; the tool itself never
  fetches (a pasted URL loads in the preview like any author image).
- Works with the engine absent: guarded engine access, CSS fallback paints
  the template readably, inspector edits and copy still work.
- The existing generator, event QA, diagnostics, and no-engine fallback keep
  working on the same `#app` DOM.

## Acceptance criteria

- [ ] The panel shows chapters, backgrounds per chapter, image URL list,
  gradient fallback, and the output field; no second generate button —
  `regen (r)` is the only button-driven rebuild.
- [ ] Regen builds chapters × backgrounds scenes; pasted URLs fill wagons in
  order; beyond the pool ⇒ local fallback; URLs never rewritten, no request
  without a pasted URL.
- [ ] `+ chapter` / `+ background` insert without redrawing the rest: the
  new chapter takes the next number, the new wagon carries a text stub,
  earlier edits survive, `scrollY` preserved, inspector selects the new
  element.
- [ ] The inspector tracks the parked background and the reading-line chapter
  while scrolling; every field edit updates the preview and the output
  field; empty morph fields remove the attribute.
- [ ] A focused inspector input is never overwritten by the 10 Hz tracker.
- [ ] Copied HTML == output field == canonical serialization: no `.snow-a`,
  no `data-snow*`, no `transform`/`will-change`/margins, no `.wtag`; all
  `data-*`, placeholders, sticks, and `type="txt"` scripts present.
- [ ] Blocked clipboard (`file://`): status explains, output selectable.
- [ ] All QA probes pass on a template that includes pasted URLs, additions,
  and inspector edits.
- [ ] With `snowfall.js` removed the template stays readable and the editor
  (add/inspect/copy) still works.

## Pitfalls

- Selection reads `Snowfall.wagons` `pos/free/y` (fresh after each frame) —
  never `getBoundingClientRect` on a transformed wagon, never a layout read
  inside the 10 Hz tick (engine absent is the one exception: no transforms
  then).
- Overlapping chains legitimately never pin: the parked count can be 0 and
  the reading-line fallback is the correct behaviour, not a bug.
- Morph and event anchors re-collect attributes only at measure — every
  attribute edit needs `refresh()`, not just geometry edits.
- Serialize filters `.snow-a` at serialization time; never delete markers
  from the live DOM (the engine reuses them across refreshes).
- A pasted URL must never close its own attribute or `url("…")` — reuse the
  existing backslash/quote/newline escaping.
- Flat chapters carry morph anchors on the `<i class="snow-fg">` carrier;
  bind chapter fields there, and show stick fields only when sticks exist.
- `regen` discarding manual edits is intended; the panel must not make a
  rebuild easy to trigger by accident while editing (no rebuild on plain
  field focus/hover).
