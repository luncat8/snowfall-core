# 0.5.5 — Region Backgrounds

## Goal

A wagon that carries a **sharp 1:1 crop over a compressed outpainted base**:
the picture parks and is pushed exactly like any other wagon, and the reader
can zoom/pan it while it is parked, with the hi-res crop always covering its
own region. Attention-quality resolution where it matters, cheap bytes
everywhere else.

Lands as a fourth optional subscriber — pure math `hdregion.js` + adapter
`snowfall-region.js` + per-book data `regions.js` — plus four engine contract
cleanups the adapter needs. A story that does not include those three files is
untouched; with JS off a `.snow-hd` wagon is a contained readable picture.

## Non-goals

- No second layout engine. `hdregion.js` is the single source of the
  layout/zoom math and is proven by a fuzz gate; the adapter never re-derives
  a fit, a clamp or a pivot.
- No runtime image work: no canvas, no `fetch`, no decoding, no per-device
  variants. One resolution per scene.
- No asset pipeline here. Scanning crops, outpainting and generating region
  entries stay in the asset repo (`tools/scan.py`, `tools/make_scene.py`).
- No scroll-driven zoom, ken-burns or parallax: zoom is a gesture, and the
  wagon itself keeps moving 1:1 with its text.
- No `iframe`, worker or CORS handling: region data is a classic `<script>`,
  which is the only thing that reads synchronously under `file://`.

## Where the code lives

Two repos exist: this engine and the asset/pipeline repo
`github.com/luncat8/HD-region`. Copying runtime both ways has already forked
in both directions — measured on this checkout:

- `HD-region/vendor/snowfall.js` is `snowfall.js` at `f5c27ed` **plus** four
  engine fixes (76 diff lines, `version` bumped `0.4` → `0.4.1`).
- `snowfall.js` at `d3b0812` differs from that vendor copy by **180 diff
  lines**: the page-span margin work (`parL`/`box`/`lastMl`, `parentPad`
  cache) exists only upstream, the cached viewport and the pos-clamp exist
  only downstream. `snowfall.js` was byte-identical from `f5c27ed` through
  `b95cc59`, so the fork is that old and neither side has the other's work.

| option | verdict | why |
|---|---|---|
| two-way vendor copies (today) | reject | proven drift; every fix must be applied twice or is silently lost, and "which copy is true" has no answer |
| git submodule at `vendor/hd-region` | reject | a GitHub source zip and a plain `git clone` both yield an *empty* directory — the region QA surface dies with no error message; SHA pinning is still a manual bump; it buys nothing for three small JS files |
| npm / workspace package | reject | runtime rules: no build, no modules, no network, `file://` double-click |
| `git subtree` merge | reject | files land physically and `subtree pull/push` syncs, so no empty-dir failure — but every sync is a remote operation with merge commits, for a sync set of three files |
| merge both repos (monorepo) | reject for now | it moves python tools, `input/`, `img/`, prototypes and five plan archives into the repo authors copy one to three files out of; the engine root stops being a drop-in. Revisit if the pipeline grows or a second engine consumer appears |
| **one trunk, one-way vendor** | **chosen** | see below |

**Rule: one trunk per kind of file, one direction of copying.**

- **snowfall-core is the trunk for runtime JS**: `snowfall.js` (core +
  wagons/morph/events), `hdregion.js` (region math), `snowfall-region.js`
  (adapter), and `test/` node gates for all three.
- **HD-region is the trunk for assets and pipeline**: `tools/*.py`, `input/`,
  `img/`, generated `regions.js`, the standalone `viewer.js` book page,
  prototypes and their plans.
- HD-region vendors runtime *from* snowfall-core only. `tools/vendor.py`
  copies the three runtime files into `vendor/` and writes
  `vendor/VERSION.txt` (`<upstream commit> <Snowfall.version> <date>`).
  Hand edits under `vendor/` are forbidden; the script is the only writer.
  `tools/vendor.py --check` fails on any disagreement, so drift is a red
  command instead of a surprise.
- No engine work happens in the asset repo. A needed engine change is made
  upstream and then re-synced. The four fixes that today live only in
  `vendor/snowfall.js` are upstreamed by this plan, so the next sync is a pure
  copy and the two trees agree again.

Why the engine owns the feature and not the reverse: the adapter is a
`Snowfall.use({measure, frame, off})` subscriber — the same shape as the three
built-in controllers — and it consumes the engine's authoritative viewport and
wagon state. The engine needs nothing from the asset repo. The dependency is
one-way by construction, which is what makes one-way vendoring honest.

What moves into this repo: `hdregion.js`, the adapter (renamed
`snowfall-region.js`), and the three node gates (`layout_test.js`,
`snowfall-integration-test.js`, `chain_sim.js`) as `test/` files. The
`regions.js` *format* is specified here; the file itself is per-book and stays
generated where the art lives. `viewer.js` + its `index.html` stay behind:
they are the no-engine QA surface, not engine code.

## Authoring contract

```html
<div class="snow-bg snow-hd" data-gap="60vh">
	<img src="img/3.avif" alt="Warehouse with robot arm">
	<img src="img/3_c.avif" alt="" aria-hidden="true">
</div>
```

- First `<img>` = base (outpainted, compressed). Second = HD crop, optional.
  Authors write two tags and no numbers: the rect comes from `REGIONS`.
- Load order in a story page, all classic `<script>`:
  `regions.js` → `hdregion.js` → `snowfall.js` → `snowfall-region.js`.
- `.snow-hd` must not use `data-mode="fixed"` or `"auto"`. Those are the two
  modes that give a wagon an explicit, centred box; every other mode gets the
  page-span box the region math assumes. On `fixed`/`auto` the adapter warns
  once and leaves the wagon alone (base image paints, no zoom).

## Coordinate contract

The engine already produces the box the math wants. A size-less wagon gets
`width = documentElement.clientWidth px` plus
`marginLeft = −parentContentLeft`, so its border box is exactly the viewport
rectangle at `x = 0` no matter which text column it was authored in, and
`height = var(--snow-vh)` = `innerHeight`. Therefore:

- The adapter sizes children against `Snowfall.viewport` — `width =
  clientWidth`, `height = innerHeight` — never `window.innerWidth` and never a
  rect read of the wagon.
- Children are `position:absolute; top:0; left:0` inside the wagon.
  `position:sticky` is a containing block for absolutely positioned
  descendants, so the child's `translate(x,y)` composes rigidly with the
  engine's `translate3d(dx,dy,0)` in every state (entering, parked, pushed,
  exiting) with no second offset and no origin correction.
- At park the engine transform is `translate3d(0,0,0)`, so wagon-local space
  *is* viewport space — which is exactly what
  `HDRegion.finalLayout(vw, vh, baseW, baseH, region, view, out)` computes.
- The adapter writes only the two child `<img>` (pixel `width`/`height` +
  `translate`). It never writes the wagon element, never adds a scroll
  listener, never runs rAF, never reads layout in `frame()`.

## Region math (`hdregion.js`)

The plan was silent on what the single source computes; a fork could not
reimplement it from the rest of the spec. This is that math, in full —
`HDRegion = {finalLayout, zoomAround, normKey}` and nothing else, so no
consumer can re-derive an internal.

State is `region = {x, y, w, h, maxZoom}` in base pixels (`x/y ≥ 0`,
`w/h` clamped inside the base, non-finite or `≤ 0` w/h read as "the whole
base"; `maxZoom < 1` or non-numeric is `4`) and `view = {zoom, vx, vy}`,
where `vx/vy` is the **base top-left in window space** at the raw (unclamped)
zoom. Fit scale at zoom 1:

```
s0 = min( max(vw/bw, vh/bh),          // cover: smallest scale covering the window
          min(vw/rw, vh/rh) )         // keep-region: largest scale with region inside
s  = s0 * clamp(zoom, 1, maxZoom)
```

Region visibility outranks coverage on purpose: outpainted filler is never
worth framing at the price of the art, so the `cover` term is *not* a cap on
`s0` — a base that cannot cover on one axis is centred there and the gap is
page background, exactly like a plain `auto` wagon that is smaller than the
window. A rect one pixel short of the base is still a rect and gets the same
treatment: "nearly whole" is an authoring smell (ship no rect then), and any
ε-band around the boundary would trade the bug back for it. A `nohd` entry (rect, no crop to paint) and an absent entry both take
the whole-base row: they are plain backgrounds and must cover, never
letterbox. Per axis (x shown, y is the mirror), with the **rest** position
`rx0 = (vw − pl)/2 − p0` and `W = bw·s`, `p0 = rx·s`, `pl = rw·s`:

```
W < vw  →  x = (vw − W)/2                    (cannot cover: center; region then
                                               fits by construction)
otherwise→ x = clamp(vx, max(vw − W, −p0), min(0, vw − p0 − pl))   if pl ≤ vw
           x = clamp(vx, vw − W, 0)                                otherwise
```

The intersection is never empty (`pl ≤ vw` and `p0 + pl ≤ W` are the guards
that made `s0` a min); an interval endpoint pair that crosses can only come
from a bad `region`, which sanitizing already rejected. `HD` child box =
`(x + p0, y + p1, pl, ph)` — by construction equal to the region rect of the
scaled base, which is the "crop always covers its region" theorem.

`finalLayout(vw, vh, bw, bh, region, view, out)` **writes the clamped values
back into `view`** (`zoom` into `[1, maxZoom]`, `vx/vy` to the axis results),
so a frame re-run is idempotent and the clamp has exactly one authority —
gesture code mutates raw state, the next layout canonicalizes. `out` carries
`{ok, s, x, y, w, h, hx, hy, hw, hh, clx, cly}`: `ok = 0` on non-finite or
non-positive inputs (caller keeps the previous frame; nothing is written);
`clx/cly` say the edge clamp moved the requested position — the pivot proof
and the fuzz gate count those, because "pivot preserved **pre-clamp**" is the
exact contract, at edges the clamp wins by design.

`zoomAround(view, px, py, k, region)` pivots raw state: `z1 = clamp(z0·k, 1,
maxZoom)`, `r = z1/z0`, `vx = px − (px − vx)·r` (same for y). Content under
the cursor is fixed exactly; only `finalLayout` may clamp. Pan is a plain
`vx += dx` at the gesture layer — no API, no second authority.

Invariants the fuzz gate proves over random viewports (320..2600 × 560..1700),
random bases/regions (1..4000 px, rect ⊆ base), zoom in `[0.5, 8]` (out-of-band
must be clamped, not obeyed) and pan in ±1e6:

- **I1** region fully visible whenever it fits at the current scale;
- **I2** base covers the window on every axis it is at least as wide as;
- **I3** `zoomAround` pivot exact on axes where `clx/cly = 0`;
- frame idempotence (second call, no mutation); finite output; `w/h = bw/bh·s`.

## Engine contract (upstream changes in 0.5.5)

Four contract cleanups, not a layout mode: sticky-chain math, wagon sizing and
subscriber order are unchanged, and built-in subscribers stay registered before
any user `use()` so a user subscriber always sees populated state in `frame()`.
`Snowfall.version` becomes `'0.5.5'`.

1. **Cached viewport.** One `vp = {width, height}`: `width =
   documentElement.clientWidth || innerWidth` (excludes the classic scrollbar;
   it is what the page-span box resolves against), `height =
   window.innerHeight` (dynamic; follows mobile URL-bar show/hide).
   `measureViewport()` updates it, writes `--snow-vw`/`--snow-vh` (both now
   follow `vp`, so `--snow-vw` becomes clientWidth-based like the box), and
   runs at the top of `wagonsMeasure()`, in `refresh()` before any subscriber
   measures, once when the instance is created, and on every scroll event
   (mobile URL-bar changes fire scroll without a resize). `coreFrame` is fed
   from `vp`, so `frame(sY, vh, vw)` and the wagon box always agree. Today the
   box is sized with `clientWidth` while `coreFrame` receives `innerWidth` —
   exactly one scrollbar of error, invisible until a child is positioned
   against it. `wagonsFrame`'s lateral-exit `vw` therefore shifts to
   clientWidth too: the exit ends flush with the visible page edge instead of
   one scrollbar past it.
2. **`Snowfall.viewport`** — read-only getter on the instance and on the
   namespace, so subscribers and debug tools stop re-measuring.
3. **`step(sY)` defaults** reuse the cached `vp` instead of re-reading
   `window.innerWidth/innerHeight`, so a gesture-triggered manual frame uses
   the same numbers as the scroll-driven one.
4. **Clamp `pos` to the parent bottom.** After `chain()`:

   ```js
   const cap = W.pBot[i] - sY - W.ext[i] - W.mb[i];
   if (W.pos[i] > cap) W.pos[i] = cap;
   ```

   Without it, once the parent scrolls past the viewport the chain leaves
   `pos = 0` (parked) while `stickyShown`'s cap goes to −∞, so
   `dy = pos − stickyShown` grows linearly with scroll: the wagon is
   translated back *onto* the screen and the scroll range inflates into a
   never-ending scroll. What the clamp guarantees per exit kind:
   - top (`dir` unset): `dy` is bounded by the chain's own maximum push
     (the cumulative `ext` of the wagons parked below — a layout constant,
     never a function of `sY`), and once every parent bottom has passed it
     converges to exactly 0: the wagon follows its sticky position
     off-screen and no wagon re-enters;
   - left/right: `dx = −cap/ext·vw` keeps growing, so the wagon parks at the
     viewport *top* but far off-screen sideways — invisible and harmless
     (unclamped, it parked visibly on-screen — that was the bug);
   - bottom: the visual position keeps sliding down, one pixel per scroll
     pixel — it never re-enters from below.
   The shared property, and what the tests assert for *every* direction: the
   per-frame change of the visual position never exceeds the scroll delta
   (lateral: never exceeds `scroll · vw/ext` by the exit projection), and a
   wagon whose parent content bottom has passed stays out of the viewport
   forever. Measured with the engine's own `chain` and `stickyShown` on a
   two-wagon layout over `sY ∈ [0, 100000]`: top-exit `max |dy|` 96030 → 0,
   push depth `min dy` −900 (one `ext`) unchanged, deep-scroll `dy → 0` in
   flat, nested and containing parent orders alike.

## Adapter (`snowfall-region.js`)

`Snowfall.use({measure, frame, off})`. State is typed arrays allocated at
measure and grown only on wagon-count increase; module-level scratch objects
(`region`, `view`, `L`) are mutated in place.

**measure()** — collect `.snow-bg.snow-hd` in scope order (a bare `.snow-hd`
without `.snow-bg` is not a wagon and gets no region handling; the fallback CSS
still paints it); take the first two `<img>` children; resolve
`REGIONS[HDRegion.normKey(base.getAttribute('src'))]`; copy `x/y/w/h/maxZoom`
into the arrays; bind one `load` listener per image; seed base sizes from
`complete && naturalWidth` so a cached image is sized on the first frame; map
each wagon to its index in `Snowfall.wagons` for gesture targeting (a
`data-static` wagon has no index — the adapter skips it, the author chose no
engine); add `snow-hd-live` to every managed wagon (see the CSS section).

`HDRegion.normKey(src)` strips query, hash and a leading `./`. It must **not**
`decodeURIComponent`: percent-decoding mangles `data:` URIs, which the harness
generator uses as image sources. It lives in `hdregion.js`, not the adapter, so
node can prove it.

**frame(sY, vh, vw)** — per wagon: read `naturalWidth`/`naturalHeight` on the
*base* image only (decode metadata, not layout — the one legal read here), and
invalidate the size cache when it changed; fall back to "the whole base is the
region" when no entry exists; copy `view` from the per-wagon arrays, call
`HDRegion.finalLayout` with the scratch objects and copy its canonicalized
`view` back; write base `width`/`height`/`transform` only when the value
changed, from `out.x/y/w/h`. Then the HD child from `out.hx/hy/hw/hh` — the
copy box, not a second derivation — again write-gated. The HD path does
**zero DOM reads**: it uses the `hdLoaded[]` flag (never `style.display`) and
cached `nwH[]/nhH[]` (never `naturalWidth`).

**Image readiness** — the HD child starts `display:none` and is unhidden by
its `load` handler, which also invalidates the size cache and calls
`Snowfall.step()`. A cached image never fires `load` again, so bind time must
check `complete && naturalWidth` and mark it loaded there, or the crop stays
hidden forever.

**Missing data** — no `REGIONS` entry: the whole base is treated as the region
and the HD stays hidden (no second `src` is ever invented). Entry without
`hd`: HD hidden. Neither case may produce a blank image or a NaN transform.

**off()** — clear both children's `width`/`height`/`transform`/`display`,
remove `snow-hd-live` and `snow-ready`, and reset the write caches, so
disabling the engine leaves a clean no-JS page.

**API** — the file exposes `window.SnowfallRegion = {count(), view(i),
setView(i, zoom, vx, vy), zoomAt(i, px, py, k), reset(i), getInspect(),
setInspect(v), onInspect}` for the harness mirror and the `qRegion` probe, and
nothing else depends on it; the probe pins state with `setView` instead of
fighting the gestures. `onInspect` is a settable callback the harness uses to
keep its checkbox in sync with the key `i`. If the document has already
finished parsing when this file loads (`readyState !== 'loading'`), the
engine's boot refresh ran before the adapter subscribed, so the adapter calls
`Snowfall.refresh()` once at subscribe time.

## Regions data (`regions.js`, per book)

```js
/* ===== GENERATED-BEGIN (tools) ===== */
REGIONS['img/3.avif'] = { x: 476, y: 101, w: 1016, h: 900, hd: 'img/3_c.avif', bw: 1984, bh: 1152 }; // rect=match conf=0.99
/* ===== GENERATED-END ===== */
/* ===== MANUAL-BEGIN ===== */
/* REGIONS['img/3.avif'].maxZoom = 2;  SCENES = ['img/3.avif']; */
/* ===== MANUAL-END ===== */
```

- One classic `<script>` next to the story page, loaded before the adapter.
  A `<script>` is exempt from CORS, so it reads synchronously under `file://`;
  a `fetch()`ed JSON sidecar does not, and first paint would be unpositioned.
- `x, y, w, h` in base pixels; `w/h` are the **detected crop** dimensions,
  never hand-typed. Optional `hd`, `bw/bh`, `title`, `maxZoom` (default 4).
- Keys are base paths relative to the book root, POSIX slashes.
- GENERATED block is rewritten by the pipeline; the MANUAL block is preserved
  byte-for-byte. Both live in the asset repo.
- The file must sit **outside `#app`** and must never be inlined into the
  source pane: scripts inserted by the source editor's `innerHTML` swap never
  execute (0.5.1), so an inline `REGIONS` would go dead after the first apply.

## JS-ready CSS

The author-side CSS is *only* the no-JS fallback — that is all a story page
must write, and it keeps pictures readable with JS off:

```css
.snow-hd { min-height: 60vh; }
.snow-hd img { display: block; width: 100%; max-height: 100vh; object-fit: contain; }
```

Everything JS-mode lives in a stylesheet the adapter injects itself, so it
works in a host page with no CSS — and it is scoped to `snow-hd-live`, the
class **measure() adds only to wagons it actually takes over**. An excluded
`data-mode="fixed"` wagon and a bare `.snow-hd` stay on the fallback rules:
the `min-height` fallback would otherwise out-size the wagon box the chain
measured, and `position:absolute` children outside a taken-over wagon have no
writer at all.

```css
html.snow-ready .snow-hd-live { min-height: 0; }
html.snow-ready .snow-hd-live > img {
	position: absolute; top: 0; left: 0; transform-origin: 0 0;
	pointer-events: none; max-width: none; max-height: none;
	object-fit: fill; width: auto; height: auto;
}
html.snow-ready .snow-hd-live > img + img { z-index: 2; }
```

The `max-width/max-height/object-fit` overrides are what strip the fallback
constraints from the two controlled children — without them,
`max-height:100vh` re-constrains the replaced-element box *after* the adapter
wrote explicit pixel dimensions, and correct math looks mispositioned.
`html.snow-ready` is added on the first measure that takes over ≥1 wagon and
removed by `off()`, so a page with the adapter loaded but the engine absent
never gets the JS-mode rules.

## Gestures

Read mode (default — the page is for reading):

- plain wheel → the engine scrolls;
- shift+wheel → zoom the parked wagon around the cursor, with
  `preventDefault()` — without it browsers map shift+wheel to *horizontal*
  page scroll.

Inspect mode (HUD checkbox or key `i`; `Esc` exits; double-click resets the
active wagon to zoom 1): wheel = zoom, drag / one finger = pan, pinch = zoom
around the midpoint, `touchmove` `preventDefault`'d so the page does not
scroll under the pan. Never an ancestor `overflow` trick — any non-visible
overflow on a wagon ancestor traps `sticky` and silently kills parking.

The gesture target is the parked wagon (`pos[i] === 0 && free[i] <= 0`), else
the last wagon with `free[i] <= vh` (one that is entering or exiting).
Handlers read no layout: they mutate `zoom/vx/vy` and call `Snowfall.step()`.
The HUD is appended to `<body>`, outside `#app`, so the engine never measures
it as an anchor.

## Harness & QA

- `regions` checkbox in the generator: `.snow-hd` wagons with two data-URI
  `<img>` (the existing generated art as base, a higher-detail render of the
  chosen rect as crop) and a matching in-memory `REGIONS` entry. No files, no
  network — region QA works from a double-clicked `index.html`. A *pasted*
  example URL becomes the base `<img>` with **no** `REGIONS` entry: its size
  is unknown in markup space, and this deliberately exercises the
  "whole base is the region, HD hidden" fallback.
- With `regions` on the generator never emits `data-mode="fixed"|"auto"` on a
  `.snow-hd` wagon (see the authoring contract).
- `inspect bg` toggle mirrors the adapter's inspect mode (checkbox →
  `setInspect`, adapter → `onInspect` callback back to the checkbox). `i` is
  free: the harness's document-level single-key handler binds
  `r t b q p d s space`, and its `Tab`/`Ctrl+Enter`/`Esc` bindings are scoped
  to the source pane, so the adapter's `i`/`Esc`/double-click on `window`
  collide with nothing.
- `save regions.js` button: writes the current in-memory `REGIONS` out in the
  GENERATED/MANUAL block format, so harness QA and the pipeline see the same
  file contract without leaving the browser.
- `qRegion` probe, one click in `QA all` (static checks read the registered
  subscriber with `Function#toString` — there is no `fetch` under `file://`):
  - pin each managed wagon with `setView(i, 1, 0, 0)` at park, compare each
    child's written `transform`/size against
    `HDRegion.finalLayout(Snowfall.viewport…)` — ±1 px at the live viewport
    (the simulated viewport shapes belong to the node gate, a GUI probe
    cannot resize the window);
  - base covers the viewport whenever possible (I2); region fully visible at
    zoom 1 (I1);
  - `zoomAt` at 2× then re-`step()`: HD child box equals the recomputed
    `finalLayout` copy (I3 rides the fuzz count), HD grew, base still covers;
  - static checks: the adapter's `frame()` body contains no
    `getBoundingClientRect`/`getComputedStyle`/`addEventListener`/`fetch`/
    arrow function/object-literal allocation, the adapter source has no
    `addEventListener('scroll'` and no `innerWidth` (it takes vh/vw from the
    engine), and the wagon element's own `transform` is byte-identical before
    and after a full zoom/pan round trip (children only, never the wagon);
  - missing-entry wagon (a pasted-URL base): painted, sized on load, HD
    never unhidden, zero console errors; excluded `data-mode="fixed"` case
    gets a synthesized throwaway wagon, one warning at most, children
    untouched, removed afterwards.

## Test matrix

- Slow pass with `regions` on: wagon geometry pixel-identical to the same
  story with `regions` off — `qOverlap`, `qAnchorAlign`, `qReversibility`,
  `qMorph`, `qEvents` all green.
- Zoom 1 → region visible, base covers when possible, at portrait 360×780,
  tablet 768×1024, desktop 1440×900, ultrawide 2560×1080.
- Zoom 2 around a corner cursor: pivot preserved pre-clamp; edge clamp may
  shift the *visible* pivot, by design, and the fuzz gate counts how often.
- Resize mid-park: children re-fit on the next frame with no jump larger than
  the resize delta.
- Cached images (second load): base sized on frame 1, HD unhidden without a
  `load` event.
- No `REGIONS` entry / entry without `hd` / `.snow-hd` with
  `data-mode="fixed"`: base paints, HD hidden, one warning at most, no NaN.
- Engine disabled (`setEnabled(false)`) or absent: children's inline styles
  cleared, no-JS contained pictures, prose readable.
- `file://` double-click: zoom, pan, pinch — no CSP or module error.
- `node test/run.js`: invariants I1/I2/I3 over 200k random layouts, the
  integration gate (viewport contract, alignment, allocation scan, static
  checks) and the pure-math gate.
- Scroll range finite: the chain simulation over a two-wagon layout,
  `sY ∈ [0, 100000]`, asserts per exit kind what the engine contract states
  — top `dy → 0` and `|dy| ≤ ext`; every direction: per-frame visual motion
  ≤ scroll delta, and after the parent bottom passes, the visual position
  never returns into the viewport. Without the clamp the same simulation must
  observe the runaway `dy` — the gate proves it fails before it may pass.

## Acceptance criteria

- [ ] `.snow-hd` parks, is pushed and exits with wagon geometry identical to a
      plain `.snow-bg`; the adapter writes children only, and the existing
      probe suite stays green with `regions` on.
- [ ] Base covers the viewport whenever possible; the region is fully visible
      at zoom 1; the HD crop covers its rect at every zoom, ±1 px, at four
      viewport shapes.
- [ ] `Snowfall.viewport.width === documentElement.clientWidth`, identical in
      `step()`, `refresh()` and subscriber `frame()`; `step(sY)` reuses it.
- [ ] Scroll range stays finite: top-exit `dy → 0` (`|dy| ≤ ext`) past the
      parent bottom, every exit direction off-screen with per-frame motion ≤
      scroll delta — verified headlessly, and the simulation proves it fails
      without the clamp.
- [ ] shift+wheel zooms around the cursor; inspect mode pans and pinches; the
      page never scrolls while panning in inspect mode; no ancestor gains
      `overflow`.
- [ ] Missing region, missing `hd` and `data-mode="fixed"` each degrade to a
      normal painted background with at most one warning.
- [ ] No-JS: contained readable pictures; `snow-ready` rules never apply
      without JS.
- [ ] `node test/run.js` green; `Snowfall.version === '0.5.5'`.
- [ ] HD-region's `tools/vendor.py --check` passes against the upstream commit
      carrying these four changes, and `vendor/VERSION.txt` names it.

## Pitfalls

- Never re-derive fit or pivot math in the adapter — call `hdregion.js`. Two
  algorithms is how the two coordinate systems of the first integration
  attempt appeared.
- `clientWidth` vs `innerWidth` is one scrollbar of error and only shows up
  once a child is positioned against the wagon. Use `Snowfall.viewport`.
- Strip the no-JS `max-height`/`object-fit` before trusting any pixel you
  wrote, or correct math reads as a positioning bug.
- `naturalWidth` is decode metadata and legal in `frame()`; `style.display`,
  `getBoundingClientRect` and `getComputedStyle` are layout and are not.
  Cache the HD's natural size at `load`, keep an `hdLoaded` flag.
- A cached image fires no `load`: check `complete && naturalWidth` at bind
  time or the crop stays hidden forever.
- `data:` URI keys must not be percent-decoded; relative paths do not need it.
- Region data must never be inline in `#app` or in the source pane — an
  `innerHTML` swap never executes scripts, so it silently dies on first apply.
- Never suspend scroll with `overflow` on an ancestor; `preventDefault` on
  `touchmove` is the only legal way to own a pan.
- Keep the gesture HUD and any region UI out of `#app`, or the engine measures
  them as anchors and every wagon below shifts.
- The pos-clamp reads `pBot`/`ext`/`mb`; if `stickyShown` or the margin
  contract ever changes, re-run the chain simulation before trusting parking.
- Do not "fix" a vendor copy in place. Upstream it, then re-sync — that is the
  whole point of the one-way rule.
