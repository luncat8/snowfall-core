# 0.5.5 — Region Backgrounds

## Goal

A wagon that carries a **sharp 1:1 crop over a compressed outpainted base**:
the picture parks and is pushed exactly like any other wagon, and the reader
can zoom/pan it while it is parked, with the hi-res crop always covering its
own region. Attention-quality resolution where it matters, cheap bytes
everywhere else.

Lands as a fourth optional subscriber — pure math `hdregion.js` + adapter
`snowfall-region.js` + per-book data `regions.js` — plus four engine contract
cleanups the adapter needs. A story that does not include those three files is
untouched; with JS off a `.snow-hd` wagon is a contained readable picture.

## Non-goals

- No second layout engine. `hdregion.js` is the single source of the
  layout/zoom math and is proven by a fuzz gate; the adapter never re-derives
  a fit, a clamp or a pivot.
- No runtime image work: no canvas, no `fetch`, no decoding, no per-device
  variants. One resolution per scene.
- No asset pipeline here. Scanning crops, outpainting and generating region
  entries stay in the asset repo (`tools/scan.py`, `tools/make_scene.py`).
- No scroll-driven zoom, ken-burns or parallax: zoom is a gesture, and the
  wagon itself keeps moving 1:1 with its text.
- No `iframe`, worker or CORS handling: region data is a classic `<script>`,
  which is the only thing that reads synchronously under `file://`.

## Where the code lives

Two repos exist: this engine and the asset/pipeline repo
`github.com/luncat8/HD-region`. Copying runtime both ways has already forked
in both directions — measured on this checkout:

- `HD-region/vendor/snowfall.js` is `snowfall.js` at `f5c27ed` **plus** four
  engine fixes (76 diff lines, `version` bumped `0.4` → `0.4.1`).
- `snowfall.js` at `d3b0812` differs from that vendor copy by **180 diff
  lines**: the page-span margin work (`parL`/`box`/`lastMl`, `parentPad`
  cache) exists only upstream, the cached viewport and the pos-clamp exist
  only downstream. `snowfall.js` was byte-identical from `f5c27ed` through
  `b95cc59`, so the fork is that old and neither side has the other's work.

| option | verdict | why |
|---|---|---|
| two-way vendor copies (today) | reject | proven drift; every fix must be applied twice or is silently lost, and "which copy is true" has no answer |
| git submodule at `vendor/hd-region` | reject | a GitHub source zip and a plain `git clone` both yield an *empty* directory — the region QA surface dies with no error message; SHA pinning is still a manual bump; it buys nothing for three small JS files |
| npm / workspace package | reject | runtime rules: no build, no modules, no network, `file://` double-click |
| `git subtree` merge | reject | files land physically and `subtree pull/push` syncs, so no empty-dir failure — but every sync is a remote operation with merge commits, for a sync set of three files |
| merge both repos (monorepo) | reject for now | it moves python tools, `input/`, `img/`, prototypes and five plan archives into the repo authors copy one to three files out of; the engine root stops being a drop-in. Revisit if the pipeline grows or a second engine consumer appears |
| **one trunk, one-way vendor** | **chosen** | see below |

**Rule: one trunk per kind of file, one direction of copying.**

- **snowfall-core is the trunk for runtime JS**: `snowfall.js` (core +
  wagons/morph/events), `hdregion.js` (region math), `snowfall-region.js`
  (adapter), and `test/` node gates for all three.
- **HD-region is the trunk for assets and pipeline**: `tools/*.py`, `input/`,
  `img/`, generated `regions.js`, the standalone `viewer.js` book page,
  prototypes and their plans.
- HD-region vendors runtime *from* snowfall-core only. `tools/vendor.py`
  copies the three runtime files into `vendor/` and writes
  `vendor/VERSION.txt` (`<upstream commit> <Snowfall.version> <date>`).
  Hand edits under `vendor/` are forbidden; the script is the only writer.
  `tools/vendor.py --check` fails on any disagreement, so drift is a red
  command instead of a surprise.
- No engine work happens in the asset repo. A needed engine change is made
  upstream and then re-synced. The four fixes that today live only in
  `vendor/snowfall.js` are upstreamed by this plan, so the next sync is a pure
  copy and the two trees agree again.

Why the engine owns the feature and not the reverse: the adapter is a
`Snowfall.use({measure, frame, off})` subscriber — the same shape as the three
built-in controllers — and it consumes the engine's authoritative viewport and
wagon state. The engine needs nothing from the asset repo. The dependency is
one-way by construction, which is what makes one-way vendoring honest.

What moves into this repo: `hdregion.js`, the adapter (renamed
`snowfall-region.js`), and HD-region's three experiment gates
(`layout_test.js`, `snowfall-integration-test.js`, `chain_sim.js`), absorbed
into `test/math.js` and `test/region.js` — layout fuzz and invariants into
region.js R1/R2, the chain/clamp simulation into math.js plus the VM proof in
R3, integration boot and static scans into R3/R4/R5. After the move the three
experiment files are deleted from HD-region; `experiments/regions_load.js`
and `encode_test.py` stay (pipeline utilities). In HD-region the superseded
`snowfall-hdregion.js` adapter and the root `hdregion.js` are deleted, the
forked `vendor/snowfall.js` is replaced by `tools/vendor.py` output, and
`snowfall-demo.html`, `viewer.js` + `index.html` repoint their `<script>` tags
at `vendor/`. The `regions.js` *format* is specified here; the file itself is
per-book and stays generated where the art lives. `viewer.js` + its
`index.html` stay behind: they are the no-engine QA surface, not engine code.
`plan-snowfall-core-integration.md` is superseded by this plan and moves to
HD-region's `archive/`.

## Authoring contract

```html
<div class="snow-bg snow-hd" data-gap="60vh">
	<img src="img/3.avif" alt="Warehouse with robot arm">
	<img src="img/3_c.avif" alt="" aria-hidden="true">
</div>
```

- First `<img>` = base (outpainted, compressed). Second = HD crop, optional.
  Authors write two tags and no numbers: the rect comes from `REGIONS`.
- Load order in a story page, all classic `<script>`:
  `regions.js` → `hdregion.js` → `snowfall.js` → `snowfall-region.js`.
- `.snow-hd` must not use `data-mode="fixed"` or `"auto"`. Those are the two
  modes that give a wagon an explicit, centred box; every other mode gets the
  page-span box the region math assumes. On `fixed`/`auto` the adapter warns
  once and leaves the wagon alone (base image paints, no zoom).

## Coordinate contract

The engine already produces the box the math wants. A size-less wagon gets
`width = documentElement.clientWidth px` plus
`marginLeft = −parentContentLeft`, so its border box is exactly the viewport
rectangle at `x = 0` no matter which text column it was authored in, and
`height = var(--snow-vh)` = `innerHeight`. Therefore:

- The adapter sizes children against `Snowfall.viewport` — `width =
  clientWidth`, `height = innerHeight` — never `window.innerWidth` and never a
  rect read of the wagon.
- Children are `position:absolute; top:0; left:0` inside the wagon.
  `position:sticky` is a containing block for absolutely positioned
  descendants, so the child's `translate(x,y)` composes rigidly with the
  engine's `translate3d(dx,dy,0)` in every state (entering, parked, pushed,
  exiting) with no second offset and no origin correction.
- At park the engine transform is `translate3d(0,0,0)`, so wagon-local space
  *is* viewport space — which is exactly what
  `HDRegion.finalLayout(vw, vh, baseW, baseH, region, view, out)` computes.
- The adapter writes only the two child `<img>` (pixel `width`/`height` +
  `translate`). It never writes the wagon element, never adds a scroll
  listener, never runs rAF, never reads layout in `frame()`.

## Engine contract (upstream changes in 0.5.5)

Four contract cleanups, not a layout mode: sticky-chain math, wagon sizing and
subscriber order are unchanged, and built-in subscribers stay registered before
any user `use()` so a user subscriber always sees populated state in `frame()`.
`Snowfall.version` becomes `'0.5.5'`.

1. **Cached viewport.** One `vp = {width, height}`: `width =
   documentElement.clientWidth` (excludes the classic scrollbar; it is what
   the page-span box resolves against), `height = window.innerHeight`
   (dynamic; follows mobile URL-bar show/hide). `measureViewport()` updates it,
   writes `--snow-vw`/`--snow-vh`, and runs at the top of `wagonsMeasure()`,
   in `refresh()` before any subscriber measures, and on every scroll event
   (mobile URL-bar changes fire scroll without a resize). `coreFrame` is fed
   from `vp`, so `frame(sY, vh, vw)` and the wagon box always agree. Today the
   box is sized with `clientWidth` while `coreFrame` receives `innerWidth` —
   exactly one scrollbar of error, invisible until a child is positioned
   against it.
2. **`Snowfall.viewport`** — read-only getter on the instance and on the
   namespace, so subscribers and debug tools stop re-measuring.
3. **`step(sY)` defaults** reuse the cached `vp` instead of re-reading
   `window.innerWidth/innerHeight`, so a gesture-triggered manual frame uses
   the same numbers as the scroll-driven one.
4. **Clamp the rendered `pos` to the parent bottom — but latch events on the
   pre-clamp chain state.** In the frame loop:

   ```js
   const raw = W.pos[i];                              // chain() output
   W.pkd[i] = (raw === 0 && fr <= 0) ? 1 : 0;         // parked latch, pre-clamp
   const cap = W.pBot[i] - sY - W.ext[i] - W.mb[i];
   const p = raw > cap ? cap : raw;                   // rendered position
   W.pos[i] = p;
   ```

   Without the clamp, once the parent scrolls past the viewport the chain
   leaves `pos = 0` (parked) while `stickyShown`'s cap goes to −∞, so
   `dy = pos − stickyShown` grows linearly with scroll: the wagon is
   translated back *onto* the screen and the scroll range inflates into a
   never-ending scroll. With the clamp `dy` converges to 0 — the wagon follows
   its sticky position off-screen — and `|dy|` is bounded by `ext`, the
   chain's own maximum push. Measured with the engine's own `chain` and
   `stickyShown` on the two-wagon demo layout over `sY ∈ [0, 100000]`:
   `max dy` 96030 → 0, `min dy` −900 unchanged, `|dy| ≤ ext` holds.

   The clamp must NOT feed the `parked` event. In a screen-flow chapter
   (`data-gap=100vh` ⇒ `ext = vh`, `mb = 0`, trigger script at the section
   end ⇒ `pBot ≈ anchor Y`) the cap equals `d − vh` — already negative
   during the *whole* time the trigger anchor is visible (`d < vh`). A
   clamped `pos === 0` test therefore can never fire `parked` there, and the
   harness probe (which simulates the unclamped chain) would report the
   wagon as pinning. So: `W.pos` keeps the clamped value (correct for
   rendering, gesture targeting and `Snowfall.wagons`), a preallocated
   `W.pkd` flag keeps the pre-clamp chain rest state, and the events
   subscriber reads `pkd` for its `parked` latch (both the live check and
   the pre-fill). `debug.parked`/`pushed` keep their 0.4 meaning (raw chain
   state), so diagnostics and probes are unchanged. The exposed clamped
   `pos` is what the adapter wants: a wagon the parent is already pushing
   out stops being a gesture target.

## Adapter (`snowfall-region.js`)

`Snowfall.use({measure, frame, off})`. State is typed arrays allocated at
measure and grown only on wagon-count increase; module-level scratch objects
(`region`, `view`, `L`) are mutated in place. Exposes a `SnowfallRegion`
global (and `module.exports` for node): `version`, `count`, `wagonEl(i)`,
`wagonIndex(i)`, `rect(i, out)` (fills `x/y/w/h/has/hd/maxZoom/baseW/baseH/
zoom/panX/panY` — `hd` is the wants-HD flag, not load state), `activeWagon()`,
`zoomActive(sx, sy, nz)`, `zoomWagon(i, sx, sy, nz)`, `resetActive()`,
`setInspect(on)`, `inspecting()`, `onInspect` callback hook.

**measure()** — collect `.snow-hd` in scope order; take the first two `<img>`
children; resolve `window.REGIONS` *every* measure (lazy — the table may load
after the engine boots or be rewritten by the harness), look up
`REGIONS[normKey(base.getAttribute('src'))]`; copy `x/y/w/h/maxZoom` into the
arrays; bind one `load` listener per image; seed base sizes from
`complete && naturalWidth` so a cached image is sized on the first frame; map
each wagon to its index in `Snowfall.wagons` for gesture targeting. Skip
wagons carrying `data-mode="fixed"` or `"auto"` with one console warning per
adapter life (those modes are engine-owned box wagons, not page-span regions);
the skipped wagon keeps whatever the engine does to it. View state
(`zoom/panX/panY`, decode caches) is preserved across measures **iff** the
wagon element at that index is identical; a swapped element is re-bound from
scratch so a generator rebuild can't inherit stale sizes.

`normKey(src)` strips query, hash and a leading `./`. It must **not**
`decodeURIComponent`: percent-decoding mangles `data:` URIs, which the harness
generator uses as image sources.

**frame(sY, vh, vw)** — per wagon: read `naturalWidth`/`naturalHeight` on the
*base* image only (decode metadata, not layout — the one legal read here), and
invalidate the size cache when it changed; fall back to "the whole base is the
region" when no entry exists; call `HDRegion.finalLayout` with the scratch
objects; write base `width`/`height`/`transform` only when the value changed.
Then the HD child, sized `region.w * s × region.h * s` at
`(L.x + region.x * s, L.y + region.y * s)`, again write-gated. The HD path
does **zero DOM reads**: it uses the `hdLoaded[]` flag (never `style.display`)
and cached `nwH[]/nhH[]` (never `naturalWidth`). `frame()` never writes on the
wagon element itself and never allocates literals; the adapter never adds a
scroll listener of its own. Early-out when `count() === 0` so a regions-free
book pays nothing. frame re-adds `snow-ready` to `<html>` if a host page
dropped it.

**Image readiness** — the HD child starts `display:none` and is unhidden by
its `load` handler, which also invalidates the size cache and calls
`Snowfall.step()`. A cached image never fires `load` again, so bind time must
check `complete && naturalWidth` and mark it loaded there, or the crop stays
hidden forever. A late-arriving HD (decoded after first paint) therefore
snaps into place on its own load event with no resize or scroll needed.

**Missing data** — no `REGIONS` entry (including a late `regions.js`): the
whole base is treated as the region and the HD stays hidden (no second `src`
is ever invented). Entry without `hd`: HD hidden. Neither case may produce a
blank image or a NaN transform.

**off()** — clear both children's `width`/`height`/`transform`/`display` and
reset the write caches, and remove `snow-ready` from `<html>`, so disabling
the engine leaves a clean no-JS page with the containment rules back in force.

**Gesture guards** — key handling (`i` toggle, `Esc` exit) skips when the
target is editable (`input/textarea/select/contentEditable`) or a modifier is
held; `dblclick` resets zoom in inspect mode; `touchmove` is
`preventDefault()`ed only while inspecting and only over a parked region
wagon, so read-mode scrolling is never touched.

## Regions data (`regions.js`, per book)

```js
/* ===== GENERATED-BEGIN (tools) ===== */
REGIONS['img/3.avif'] = { x: 476, y: 101, w: 1016, h: 900, hd: 'img/3_c.avif', bw: 1984, bh: 1152 }; // rect=match conf=0.99
/* ===== GENERATED-END ===== */
/* ===== MANUAL-BEGIN ===== */
/* REGIONS['img/3.avif'].maxZoom = 2;  SCENES = ['img/3.avif']; */
/* ===== MANUAL-END ===== */
```

- One classic `<script>` next to the story page, loaded before the adapter.
  A `<script>` is exempt from CORS, so it reads synchronously under `file://`;
  a `fetch()`ed JSON sidecar does not, and first paint would be unpositioned.
- `x, y, w, h` in base pixels; `w/h` are the **detected crop** dimensions,
  never hand-typed. Optional `hd`, `bw/bh`, `title`, `maxZoom` (default 4).
- Keys are base paths relative to the book root, POSIX slashes.
- GENERATED block is rewritten by the pipeline; the MANUAL block is preserved
  byte-for-byte. Both live in the asset repo.
- The file must sit **outside `#app`** and must never be inlined into the
  source pane: scripts inserted by the source editor's `innerHTML` swap never
  execute (0.5.1), so an inline `REGIONS` would go dead after the first apply.

## JS-ready CSS

The no-JS fallback keeps pictures readable:

```css
.snow-hd { min-height: 60vh; }
.snow-hd img { display: block; width: 100%; max-height: 100vh; object-fit: contain; }
```

The adapter adds `snow-ready` to `<html>` from its first frame (not at load —
`off()` and re-enable must toggle it), and the story stylesheet
then drops the constraints on the two controlled children:

```css
html.snow-ready .snow-hd { min-height: 0; }
html.snow-ready .snow-hd img {
	max-width: none !important; max-height: none !important;
	object-fit: fill !important;
}
```

Without that, `max-height:100vh` / `object-fit:contain` re-constrain the
replaced-element box *after* the adapter wrote explicit pixel dimensions, and
correct math looks mispositioned. The adapter also injects its own child rule
(`position:absolute; top:0; left:0; transform-origin:0 0; pointer-events:none`
+ `z-index:2` on the second child) so it works in a host page with no CSS.

## Gestures

Read mode (default — the page is for reading):

- plain wheel → the engine scrolls;
- shift+wheel → zoom the parked wagon around the cursor, with
  `preventDefault()` — without it browsers map shift+wheel to *horizontal*
  page scroll.

Inspect mode (HUD checkbox or key `i`; `Esc` exits; double-click resets the
active wagon to zoom 1): wheel = zoom, drag / one finger = pan, pinch = zoom
around the midpoint, `touchmove` `preventDefault`'d so the page does not
scroll under the pan. Never an ancestor `overflow` trick — any non-visible
overflow on a wagon ancestor traps `sticky` and silently kills parking.

The gesture target is the parked wagon (`pos[i] === 0 && free[i] <= 0`, on the
clamped `pos` the engine now exposes), else the last wagon with
`free[i] <= vh` (one that is entering or exiting). Handlers read no layout:
they mutate `zoom/vx/vy` and call `Snowfall.step()`. The HUD is appended to
`<body>`, outside `#app`, so the engine never measures it as an anchor; the
harness stylesheet hides it (`#snow-region-hud { display: none; }`) because
the harness has its own `inspect bg` mirror.

## Harness & QA

- `regions` checkbox in the generator: `.snow-hd` wagons with two data-URI
  `<img>` (the existing generated art as base, a higher-detail render of the
  chosen rect as crop) and a matching in-memory `REGIONS` entry. No files, no
  network — region QA works from a double-clicked `index.html`. `artURI()`
  returns the bare data URI and `cssURI()` wraps it for `url()`; the wagon
  HTML needs the bare form (`<img src="data:…">`) or `getAttribute('src')`
  never matches the table key.
- Region entries alternate by wagon index (`k % 3`): full entry with HD crop
  and `maxZoom`, entry without `hd` (HD child stays hidden), no entry at all
  (whole-base fallback) — one build exercises every degrade path. Rects come
  from a private `mulberry32(hash32(tag + '·rect'))` so a rebuild is stable
  and never clashes with the art RNG. `build()` resets `window.REGIONS = {}`
  before regenerating; the pasted-source path emits single-image wagons with
  no entry (fallback).
- With `regions` on the generator never emits `data-mode="fixed"|"auto"` on a
  `.snow-hd` wagon (see the authoring contract) — it falls back to `cover`.
- The source serializer treats `<img>` as a void tag: without that, round-
  tripping a regions story through the source pane emits `</img>`, which the
  browser's parser turns into stray elements and corrupts the rebuild.
- `inspect bg` toggle mirrors the adapter's inspect mode through
  `SnowfallRegion.setInspect` and back via the `onInspect` hook. `i` is free:
  the harness's document-level single-key handler binds `r t b q p d s space`,
  and its `Tab`/`Ctrl+Enter`/`Esc` bindings are scoped to the source pane, so
  the adapter's `i`/`Esc`/double-click on `window` collide with nothing.
- `save qa ↓` button: serializes the last QA result to a Blob download
  (`snowfall-qa.txt`) for pasting into a report — file:// pages cannot write
  files any other way.
- `qRegion` probe, one click in `QA all`:
  - the adapter must be subscriber #4 (`Snowfall.default.subs[3]`);
  - at park (detected by scrolling to `Math.ceil(W.y[wi])` and requiring
    `pos === 0 && free <= 0`, else the row is skipped, not failed), compare
    each child's written `transform`/size against
    `HDRegion.finalLayout(Snowfall.viewport…)` — ±1 px at the live viewport
    (the four simulated viewport shapes belong to the node gate, a GUI probe
    cannot resize the window);
  - base covers the viewport whenever possible (I2); region fully visible at
    zoom 1 (I1);
  - after `zoomActive(center, 2)`: zoom is 2, HD child grew, pivot preserved
    pre-clamp (I3), base still covers, the wagon element's own transform is
    untouched, `resetActive()` restores zoom 1;
  - static source checks run in the GUI, no network: `String(sub.frame)` with
    comments stripped — no object/array literal in the frame body, no
    `wagonEls[…].style` write, no `addEventListener('scroll'` anywhere in the
    adapter source;
  - `hd === 0` wagons: HD child `display: none`;
  - zero `console.error` through the whole probe.

## Acceptance criteria

- [ ] `.snow-hd` parks, is pushed and exits with wagon geometry identical to a
      plain `.snow-bg`; the adapter writes children only, and the existing
      probe suite stays green with `regions` on.
- [ ] Base covers the viewport whenever possible; the region is fully visible
      at zoom 1; the HD crop covers its rect at every zoom, ±1 px, at four
      viewport shapes.
- [ ] `Snowfall.viewport.width === documentElement.clientWidth`, identical in
      `step()`, `refresh()` and subscriber `frame()`; `step(sY)` reuses it.
- [ ] Scroll range stays finite: `|dy| ≤ ext` past the parent bottom, verified
      headlessly; `parked`/`pushed` events still fire exactly once per
      chapter (screen-flow included) with regions on, because the latch reads
      the pre-clamp chain state.
- [ ] `SnowfallRegion` mirrors the adapter: `count`/`rect(i, out)`/
  `activeWagon`/`zoomActive`/`resetActive`/`setInspect` agree with the DOM
  the probe reads.
- [ ] shift+wheel zooms around the cursor; inspect mode pans and pinches; the
      page never scrolls while panning in inspect mode; no ancestor gains
      `overflow`.

## Pitfalls

- Never re-derive fit or pivot math in the adapter — call `hdregion.js`. Two
  algorithms is how the two coordinate systems of the first integration
  attempt appeared.
- `clientWidth` vs `innerWidth` is one scrollbar of error and only shows up
  once a child is positioned against the wagon. Use `Snowfall.viewport`.
- Strip the no-JS `max-height`/`object-fit` before trusting any pixel you
  wrote, or correct math reads as a positioning bug.
- `naturalWidth` is decode metadata and legal in `frame()`; `style.display`,
  `getBoundingClientRect` and `getComputedStyle` are layout and are not.
  Cache the HD's natural size at `load`, keep an `hdLoaded` flag.
- A cached image fires no `load`: check `complete && naturalWidth` at bind
  time or the crop stays hidden forever.
- `data:` URI keys must not be percent-decoded; relative paths do not need it.
- Region data must never be inline in `#app` or in the source pane — an
  `innerHTML` swap never executes scripts, so it silently dies on first apply.
- Never suspend scroll with `overflow` on an ancestor; `preventDefault` on
  `touchmove` is the only legal way to own a pan.
- Keep the gesture HUD and any region UI out of `#app`, or the engine measures
  them as anchors and every wagon below shifts.
- The pos-clamp reads `pBot`/`ext`/`mb`; if `stickyShown` or the margin
  contract ever changes, re-run the chain simulation before trusting parking.
- Never latch `parked` on the clamped `pos`: for a screen-flow wagon
  (`gap=100vh`) the cap `pBot − sY − ext − mb` is negative the whole time
  the trigger anchor is visible, so a clamp-aware `pos === 0` test silently
  never parks. Latch on the pre-clamp chain rest state (`W.pkd`).
- Resolve `window.REGIONS` lazily at every measure. The table may load after
  the engine boots, and the harness rebuilds it in place; a boot-time capture
  pins an empty or stale table forever.
- Serialize `<img>` as a void tag. `</img>` from a source-pane round-trip
  makes the browser parser invent stray elements and corrupts the rebuild.
- Skip the `i`/`Esc` key handling while the target is editable or a modifier
  is held, or typing in the source pane toggles inspect mode mid-word.
- `snow-ready` must be removed by `off()` and re-added by `frame()`, not
  added once at load: `setEnabled(false)` has to hand the page back to the
  no-JS containment rules, and a later enable has to re-own the children.
- The engine collects `.snow-bg` from the scope element
  (`app.querySelectorAll`), not from `document` — VM shims must mirror that.
- Static source scans must strip comments first: a comment mentioning an
  object literal or `.style` otherwise fails the allocation/write scans.
- Do not "fix" a vendor copy in place. Upstream it, then re-sync — that is the
  whole point of the one-way rule.
