# 0.4.1 — Script Policies, Choices and Save Slots

## Goal

Scripts gain three per-script execution policies — **repeat**, **direction**,
**skip** — and a persistent result store, so a chapter the reader scrolls past
still leaves the world in the state the reader's own earlier choice produced.
One interactive primitive (`Snowfall.ask`) covers dialog choices, minigames and
location walks alike: played live it prompts and records; skipped it replays
the recorded value, or the author's default when it was never played.

The worked case this plan is written against:

```html
<script type="txt" event="center" data-id="ch3-mine">
Snowfall.ask('gold.ch3', 1, null, function (gold, mode) {
	Snowlog('ch3 pays ' + gold + ' gold (' + mode + ')');
	Snowlog('purse: ' + Snowfall.sum('gold.'));
});
</script>
```

The reader plays the minigame and wins ⇒ `ch3 pays 2 gold (live)`, and `2` is
stored under `gold.ch3`. Next visit, scrolled past ⇒ `ch3 pays 2 gold
(saved)`. Never played at all ⇒ `ch3 pays 1 gold (default)`. The purse is a
*derived* total over the `gold.*` keys, so replaying or re-playing a chapter
overwrites that chapter's share instead of adding to it twice.

Dialog choices and location walks are the same call with a different `options`
table; every script result has a default path.

0.4 stays intact: an unchanged story keeps firing exactly as before, because
all three policies default to today's behaviour.

## Non-goals

- No story graph, no branching chapters, no `goto`. The engine still only
  decides *when*; scripts decide *what*.
- No rollback. The engine replays a recorded outcome; it does not undo the DOM
  effects of an earlier pass. **State persists, DOM does not** — the page is
  rebuilt from source (0.5.1), so every visible consequence has to be
  re-applied by the scripts themselves on each pass.
- No async, no promises, no `await` in snippets. `ask` *declares* a prompt and
  takes a continuation instead of blocking.
- No scroll-locking / paged VN mode. A prompt the reader scrolls away from is
  answered by the skip path — that is the rule, not a failure.
- No multi-slot UI, no cloud sync, no encryption, no server, no schema
  migration tooling.

## DOM contract

```html
<script type="txt" event="center"
	data-id="ch3-mine"
	data-times="many"
	data-dir="forward"
	data-skip="replay">
```

| attribute | values | default | meaning |
|---|---|---|---|
| `data-times` | `many` \| `once` | `many` | `once` fires at most once **per save slot**, surviving reloads and re-arms |
| `data-dir` | `forward` \| `both` | `forward` | `both` fires the same thresholds while scrolling up too |
| `data-skip` | `replay` \| `none` | `replay` | `none` never runs this script on `skip` |
| `data-id` | any string | derived | stable identity for `once` bits and for keys derived from it |

- `data-id` is required for anything that must survive editing. Without it the
  engine derives `id = fnv1a(code)` — **never an ordinal**: ordinals shift the
  moment the author adds a chapter, and an ordinal-keyed `once` bit would
  silence the wrong script.
- Duplicate `data-id` ⇒ one console warning; first in document order wins, the
  rest behave as `many`.
- Policies are per *script*, not per anchor. One anchor can carry a `once`
  script and a `many` script (0.4 anchor sharing is unchanged).

## Execution semantics

State per anchor stays two `Uint8Array`s: the 0.4 latch bits
(`1 view | 2 center | 4 parked | 8 end | 16 skip`) plus a new `side` byte
holding the last side of each of the five thresholds. A `pol` byte per script
carries the three policy bits. `eventsFrame` stays O(A) integer compares.

- **`many` (default)** — today's behaviour: fire on the set edge, re-arm after
  `hysteresis` px of clear space on the opposite side.
- **`once`** — `eventsMeasure` pre-sets *every* latch bit of a script whose
  `fired` bit is in the store, so it cannot fire this session; `fireAnchor`
  sets the store bit at the first fire. `once` + `both` = one firing total,
  whichever leg arrives first.
- **`forward` vs `both`** — `forward` scripts consult the latch byte exactly
  as in 0.4. `both` scripts consult `side`: the threshold is
  `d < T` (`T = vh`, `vh*0.5`, `0`, plus the wagon-pin test for `parked`), and
  the event fires whenever the side changes in either direction, with
  `detail.dir = +1` (reading down) or `−1` (reading up). `skip` is
  direction-agnostic and never fires on the reverse leg — "you never read it"
  has no upward variant.
- **`skip` + `replay` (default)** — fires on the 0.4 condition (an anchor that
  reached `end` without `view`), and the snippet runs in **replay mode**:
  `ask` resolves synchronously from the store and renders nothing, so a
  skipped chapter is state-complete inside the same frame.
- **`skip` + `none`** — the `skip` delivery is filtered for that script inside
  `fireAnchor`. The anchor's `skip` bit is *not* cleared: 0.4 ORs all five
  `decl` bits into a shared anchor, and clearing it would silence the
  script's siblings.

Direction comes from the frame's scroll delta against a cached `lastSY`. A
zero-delta frame keeps the previous non-zero sign, so `detail.dir` never
flickers at rest.

The global reversibility invariant (0.0) covers transform, colour and class.
Events are edge-triggered by design and therefore history-dependent; `both` is
an author asking for both edges, not a break in the math.

## Result store

One JSON document per story and slot, flat maps only:

```json
{ "v": 1, "story": "my-book", "slot": 0, "at": 1758240000,
  "vars": { "flags.metIvo": true },
  "keys": { "gold.ch3": 2, "ch3.door": "knock" },
  "fired": { "ch3-mine": 1 } }
```

- `vars` — author story state: `Snowfall.get(key, fallback)` /
  `Snowfall.set(key, value)`. JSON scalars only (string, number, boolean,
  null); anything else warns once and is dropped, never serialized half-way.
- `keys` — recorded `ask` outcomes.
- `fired` — `data-times="once"` bits, keyed by script id.
- Backend: `localStorage['snowfall:' + story + ':' + slot]`. `story` comes
  from `<html data-story="…">`, else `<meta name="story">`, else the pathname
  tail. **Never a bare key**: on `file://` Chrome gives every local document
  one shared opaque origin, so unprefixed keys collide across books.
- Any `localStorage` throw (private mode, disabled, quota) ⇒ in-memory store,
  one console warning, `Snowfall.store.persistent === false`. The page keeps
  working; the harness shows the flag in diagnostics.
- Load is synchronous at engine boot, **before** the first `refresh()`, so
  `once` pre-fill sees the store. Autosave is debounced 250 ms after any
  write, flushed on `pagehide` and before any export. The store is never read
  or written inside `frame()`.

API on the namespace (and therefore inside every snippet):

```js
Snowfall.get(key, fallback)      Snowfall.set(key, value)
Snowfall.sum(prefix)             // Σ of stored numbers under prefix — derived totals
Snowfall.ask(key, fallback, options, done)   Snowfall.answer(key, value)
Snowfall.save()                  Snowfall.load(json)
Snowfall.exportJSON()            Snowfall.importJSON(text)
Snowfall.reset({ vars, keys, fired })
Snowfall.store                   // { persistent, dirty, counts } — read-only debug
```

`sum` walks `vars` then `keys` and adds the numeric values whose key starts
with `prefix` (non-numeric and missing entries count 0). It exists so a
wallet, a reputation or a found-items count is a *derived* value over
per-chapter shares: re-running or replaying a chapter overwrites its own share
instead of granting twice. It iterates the stored map and allocates nothing.

`reset()` with no argument clears the current slot (harness `clear save`);
with a mask it clears only the named sections, which is what QA needs to test
`once` without losing recorded choices.

## Choice primitive

`Snowfall.ask(key, fallback, options, done)`

- `options` — a flat table `[['Knock', 'knock'], ['Leave', 'leave']]` ⇒ the
  engine renders the prompt. `null` ⇒ the author's own UI owns the prompt and
  must call `Snowfall.answer(key, value)`.
- `done(value, mode)` — called exactly once, `mode` ∈ `'live'` (just
  answered), `'saved'` (replayed from the store), `'default'` (fallback, never
  played). In replay mode it runs synchronously inside the script's own fire.
- `ask` returns nothing. The continuation is the only channel — that is what
  keeps snippets synchronous and makes the skip path free.
- A live answer is recorded **before** `done` runs, so a continuation that
  throws (or a page closed right after the click) still leaves the outcome
  saved. `done` reads the store, it does not feed it.
- **Abandon rule.** If the anchor reaches `end` before an answer, the engine
  resolves with the stored value or the fallback (`mode = 'saved'` or
  `'default'`) and the anchor counts as skipped. One rule, no timers.
- Exactly-once: one pending slot per key, cleared on answer, on abandon and on
  `refresh()`. `Snowfall.answer` for an unknown or already-resolved key warns
  once and is ignored. A second `ask` for an already-pending key is likewise
  ignored (warn once); the first pending wins.
- Built-in prompt: a fixed panel appended to `<body>` (outside `#app`, so the
  engine never measures it as an anchor), injected CSS, `z-index: 60` — above
  `.snow-stick` (5) and the reading hud (9), below the harness panels (110).
  No ancestor gains `overflow`.
- Host hook: `Snowfall.onChoice = function (req, resolve) { … }` replaces the
  built-in panel for a story with its own chrome; `resolve(value)` is the
  engine's continuation and `req` is `{ key, fallback, options, y, id }`.

## `detail` (extended)

```js
{ el, event, y, scrollY, wagon, morph, dir, mode }
```

`dir` = `+1`/`−1` frame direction; `mode` = `'live'` for a normal fire,
`'replay'` for a `skip` replay. Still one reused object mutated in place, so
`frame()` allocates nothing.

## Interaction with the other plans

- **0.4 pre-fill still wins at load**: a cold load mid-document fires nothing
  even when a save exists. The store only pre-sets `once` latches, on top of
  the pre-fill, never instead of it.
- **0.5.1 source swap** uses `refresh()`, which re-reads `fired`. An edited
  snippet gets a new derived id and therefore fires again — intended, since an
  edited script *is* a new script; `data-id` is how an author keeps an identity
  stable across edits.
- **0.5.5 region adapter** is a sibling subscriber and shares no state. Both
  call `Snowfall.step()`; neither may touch the other's arrays.

## Harness

- Generator emits, per story: one `ask` script with an `options` table (dialog
  choice), one `ask` with `options = null` plus a button that calls
  `Snowfall.answer` (minigame), one `data-times="once"` script and one
  `data-dir="both"` script, so every policy is exercised by `QA all`.
- Diagnostics show `store.persistent`, the counts of `vars`/`keys`/`fired`, and
  the pending prompt count.
- Buttons, per the sandbox rule (in-GUI, no npm): `save ↓` downloads the JSON,
  `load ↑` imports it, `clear save` calls `reset()`.
- `qChoices` probe:
  - live `ask` renders a prompt at the fire; a click stores the value and runs
    `done` once with `mode = 'live'`;
  - `Snowfall.answer` resolves an `options = null` prompt identically;
  - abandon: scrolling past without answering calls `done` exactly once, with
    the stored value or the fallback, and never again on later frames;
  - reload with a save present: skipped chapter ⇒ `mode = 'saved'` and the
    recorded value; never-played chapter ⇒ `mode = 'default'` and the
    fallback;
  - `data-times="once"`: one fire over two full passes, zero after reload,
    one again after `clear save`;
  - `data-dir="both"`: one fire per threshold on each leg with the right
    `detail.dir`, while a `forward` sibling fires only going down;
  - `data-skip="none"`: a flick fires the siblings and not this script;
  - `once` + `both`: exactly one fire, whichever leg comes first;
  - export/import: byte-identical JSON, and `refresh()` after import respects
    `fired`;
  - injected `localStorage` throw: in-memory fallback, no exception,
    `persistent === false`;
  - cold load mid-document with a save present: zero events;
  - `eventsFrame` source contains no store access and no allocation.

## Acceptance criteria

- [x] The three policies are per script, default to `many`/`forward`/`replay`,
      and an unmodified 0.4 story fires identically (`qEvents` unchanged).
- [x] A skipped chapter reproduces the reader's own earlier result, and the
      author's fallback when there is none — verified across a reload.
- [x] `ask` runs its continuation exactly once in every mode, including
      abandon, and never renders UI in replay mode.
- [x] `data-times="once"` survives reload, source re-apply and re-arm; `clear
      save` restores the fire.
- [x] `data-dir="both"` fires on both legs with a correct `detail.dir`;
      `forward` fires on the forward leg only; `skip` never fires in reverse.
- [x] The store round-trips byte-identically through export/import, degrades
      to memory without throwing, and is prefixed by story id.
- [x] No store access and no allocation inside `frame()`; autosave is a timer
      and flushes on `pagehide`.
- [x] Engine absent or JS off: prompts never appear, no error, prose readable.
- [x] `qEvents`, `qMorph`, `qOverlap`, `qAnchorAlign`, `qReversibility` and
      (with 0.5.5) `qRegion` stay green; `node test/run.js` green, including
      `test/scripts.js`: the store round-trip (serialize/parse/reset, scalar
      filtering, story-id prefix) and the `once`/`both`/`skip` state machine
      driven by synthetic scroll sequences.

## Pitfalls

- `file://` gives every local document one shared opaque origin in Chrome:
  always prefix the key with the story id. A bare `'snowfall-save'` key will
  leak one book's gold into another.
- Load the store before the first `refresh()`, or `once` scripts re-fire after
  every reload and the policy looks broken only in a browser.
- `once` lives in the store, not in `E.flags`: flags are per-session and are
  zeroed by `measure`, so a flag-only implementation resets on every resize.
- Filter `data-skip="none"` in `fireAnchor`, never by clearing the anchor's
  `skip` bit — shared anchors would silence their siblings (0.4).
- Resolve each `ask` exactly once. Both the click path and the `end` path can
  arrive, and `refresh()` can arrive between them.
- Prompts live on `<body>`, never inside `#app` (measured as an anchor, shifts
  every wagon below) and never add `overflow` to an ancestor (traps `sticky`).
- Snippets stay synchronous: `ask` declares a prompt and takes a continuation.
  Never `await` a click inside a snippet — the engine has no promise plumbing
  and the scroll book will move on without it.
- Write idempotent effects. A replayed skip *is* the grant: `gold += value`
  double-grants when the reader later plays the chapter for real. Derive the
  total instead — per-chapter `ask` keys plus `Snowfall.sum(prefix)`, as in
  the worked case — or guard with an explicit "granted" key. This is the one
  mistake the engine cannot catch, so it belongs in the authoring notes.
- `detail.dir` comes from the frame delta; cache the last non-zero sign or a
  resting frame flips it and a `both` script re-fires at a standstill.
- Autosave on a debounce only, flushed at `pagehide`; never inside `frame()`,
  and never per keystroke of a minigame's internal state — persist results,
  not intermediate UI.
- JSON scalars only. Persisting an object graph invites cycles, and a quota
  error mid-serialize must not lose the choices written before it.
