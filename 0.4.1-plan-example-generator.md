# 0.4.1 — Pasted Image Example Generator

## Goal

Add a small, file-friendly authoring tool to the harness. A user pastes one
image URL per line, chooses the existing wagon settings, and presses one
button to produce a complete example container. The same markup is rendered
in the test story so it exercises the real wagon, gradient, style, stick, and
script-event paths instead of being a disconnected code sample.

## Controls

The tool lives in the fixed left `#gen` panel:

- `image URLs, one per line` accepts blank lines and ignores lines beginning
  with `#`.
- `include gradient` adds one local CSS gradient scene after the pasted
  images. It keeps the feature useful with no network and gives a known-good
  visual comparison.
- `generate HTML` replaces the example preview with the current list and
  current wagon settings.
- `copy outerHTML` copies the complete `.snow-example-container`, not only
  its children. A visible status message reports success or a blocked copy.

The existing `mode`, `size`, `data-dir`, `flow`, `nesting`, `sticks`,
`data-bg/fg/style`, and `script events` controls are the settings source. A
`mixed` choice is deterministic for the current harness seed.

## Generated contract

```html
<div class="snow-example-container" data-snowfall-example="image-list">
	<div class="snow-example-heading">Pasted examples</div>
	<section class="snow-example-scene">
		<h3 class="snow-example-title">pasted image 1</h3>
		<div class="snow-bg" data-example-kind="image" data-mode="cover"
			style="background-image:url(&quot;scene.jpg&quot;)"></div>
	</section>
</div>
```

- Every visual is a normal `.snow-bg`, so the existing engine owns its
  dimensions, sticky parking, direction, and transform.
- Pasted values are escaped for both HTML attributes and quoted CSS URLs.
  The generated gradient is a static local CSS `linear-gradient`.
- Optional scene data attributes, sticks, and inert `type="txt"` event blocks
  follow the existing generator vocabulary.
- The clean generated outerHTML is kept separately from the live preview, so
  engine markers, transforms, and measurement styles never leak into copied
  markup.
- The preview is appended before the existing tail; regular generated
  chapters remain intact and the example scenes participate in the same
  engine refresh and diagnostics.

## Runtime rules

- No build step, modules, network dependency, or persistence of pasted URLs in
  the location hash.
- Clipboard API is preferred. A hidden textarea and `execCommand('copy')`
  provide the `file://` fallback.
- An empty list is valid when the gradient is enabled. If both sources and
  gradient are absent, generation clears the preview and reports the action.

## Acceptance criteria

- [ ] The left tools show the paste field, generate button, copy button, and
  generated HTML output.
- [ ] One generated scene appears for every non-empty pasted line, plus one
  local gradient when enabled.
- [ ] Changing an existing wagon setting and pressing generate changes both
  the preview and the copied container markup.
- [ ] Copied output starts with the complete
  `.snow-example-container` element and is valid standalone Snowfall markup.
- [ ] External image URLs are not silently rewritten; the gradient remains
  local and does not add a network request.
- [ ] Existing generator, event QA, and no-engine fallback still work after
  the example preview is generated.
- [ ] Opening `index.html` directly remains supported; blocked clipboard access
  leaves the output selectable and explains what happened.
