# 0.0 — Snowfall Plan Overview

## Concept

Prose scrolls; background pictures ride with it like train wagons. A wagon
moves 1:1 with its own DOM text position, parks at the viewport edge when it
arrives, and leaves only when the next wagon below collides with its bottom
and pushes it out. Parked text slots (captions at the top, location tags at
the bottom) use the same idea with an author-chosen park position. Page theme
(colours, classes) morphs between scroll anchors so a chapter change reads
like a sunset or a door opening onto a bright room — interactive, never a
blink. Inert `<script type="txt" event=...>` blocks fire on scroll states.

Everything is free-placed in the DOM: no strict `<section>` tree, no required
wrapper, no renpy-like DSL. Backgrounds are not owned by sections — an author
may keep one across sections or introduce a new one between two text lines.
`file://` friendly, no build, no modules, no network, classic `<script>` tags.
With JS off the page is still readable prose; markup stays close to epub
syntax so stories convert easily.

## Prototype comparison (what was reviewed, what was taken)

Reviewed: `prototype/GLM5.2-vn-engine-v2.html`, `prototype/GLM5.2-vn-engine-v3.html`,
`prototype/gpt-5.6-luna-medium.html`, `prototype/kimi-K26-A.html`,
`prototype/0.2-train-cars-sticky.html`, and `VNS_e4ar` `main` + branch `1`.

| prototype | verdict | take | reject / why |
|---|---|---|---|
| kimi-K26-A | proven smooth, minimal core | synchronous `scroll` handler writing `translate3d` (no rAF lag); own-wagon `data-dir` exit semantics; back-to-front push sweep | section-wrapped sticky scope (parent ends drag wagons early); per-scroll string concat without write gating; no events/morph/harness/size contract |
| 0.2-train-cars-sticky | core architecture winner | `position:sticky;top:0` parking on the compositor thread, JS only for the push phase; push fraction for lateral exits | pusher-dictates `data-dir` (surprising: a wagon exits differently depending on who pushes it — own-exit is predictable); `offsetTop` walk (fragile under positioned ancestors — markers instead); per-scroll allocations |
| VNS_e4ar `main` | rigorous engine, wrong parking layer | 1D chain math `pos[i]=min(park[i],pos[i+1]-ext[i])`; marker-based anchors; measure/frame split; typed arrays; write gating; linear-light colour lerp; edge-triggered `view\|center\|parked\|end\|skip` with hysteresis-on-reset; generator+harness+QA probes+node gates | hoisted `#vns-layer` with fully JS-driven parking (rAF lag on fast scroll — compositor sticky parks with zero lag); singleton-only API; URL-flag control |
| VNS_e4ar branch `1` | take the API, not the math | `new VNS(options)` lifecycle: `setEnabled`, `destroy`, `onFrame`; `data-w`/`data-h`; published `--vns-w/--vns-h` | per-frame `getBoundingClientRect` (layout thrash); 2D coupled push math (bottom-exit jumps previous wagon back on screen); unhoisted `fixed` (breaks under transformed ancestors); sRGB lerp; section-tied events |
| GLM v2/v3 | rich demo, weak engine | theme interpolation across CSS custom properties; parked badge / progress / dots HUD ideas; v3 auto-discovery of `.bg` in free DOM order | section-anchored cars (violates free placement); opacity crossfade instead of geometric push; all wagons forced 100vh fixed layers; per-frame `getComputedStyle` + `innerHTML` HUD (allocations, forced style); lorem filler; `setInterval` tickers |
| gpt-5.6-luna-medium | clean authoring sketch | `data-bg-size` mode vocabulary; fixed `.bg-visual` separated from in-flow anchor; toolbar/test-page idea | measures layout every frame (thrash); events fire once ever (no re-arm, reverse/repass dead); no `parked`, no `data-dir`; rAF-coalesced writes (lag); string-concat transforms without gating |

Architecture decision: **sticky park + JS push.**

- Parking (`max(free,0)`) runs on the compositor via `position:sticky` — zero
  JS, zero lag, no rAF delay. This is the kimi/0.2 proof.
- The push chain and lateral/bottom exits run in a **synchronous** passive
  scroll handler as pure `scrollY` math on typed arrays, writing only
  `transform` deltas (`desired − stickyShown`), write-gated. No rAF chain, so
  an idle page does nothing and a fast flick never outruns the engine.
- VNS `main` contributes the chain theorem, markers, morph math, event state
  machine, and harness/QA/test design; branch `1` contributes the lifecycle
  API. GLM/luna contribute HUD and authoring vocabulary only.

## Files

| file | role | plan |
|---|---|---|
| `index.html` | demo/QA shell: form + `#app` + `<script src>` tags | 0.1 |
| `harness.css` | author-side look of the demo: type, panels, QA classes | 0.1 |
| `harness.js` | content generator, diagnostics, auto-scroll, QA probes, template/source editor | 0.1, 0.5.0–0.5.1 |
| `snowfall.js` | engine: core loop + shared anchors + wagons + morph + events | 0.2–0.4 |
| `test/math.js` | `node test/math.js` — pure math, no DOM, zero deps | 0.2–0.4 |

`snowfall.js` injects its own `<style>` so it works in any host page; the host
only declares `.snow-bg` pictures and optional `data-*`. Every `.js` file is a
classic script that is also `require()`-able under Node
(`if (typeof module !== 'undefined') module.exports = Snowfall;`) with zero
DOM touch at load time, so all math is unit-testable headless.

## Plan sequence — implement in order

1. **0.1 Test harness** — generator + diagnostics + QA probes. Lands first:
   it is the manual QA surface for every later plan and must work with no
   engine present so that "engine absent" and "engine wrong" are visually
   different states. Depends on nothing.
2. **0.2 Wagon engine** — the core. Also owns the shared plumbing every later
   plan reuses: one synchronous scroll handler, one anchor-measurement pass,
   `refresh()`, `data-*` authoring API, parked-text slots. Park/push math,
   size modes, `data-dir`, reversible.
3. **0.3 Style morph** — second subscriber. Lerps colours and swaps classes
   between `[data-bg]/[data-fg]/[data-style]` anchors. No own listener, no
   own loop. Works with wagons off.
4. **0.4 Script events** — third subscriber. Edge-triggered
   `view|center|parked|end|skip` on inert `script[type=txt]`. `parked` reads
   wagon state, degrades gracefully when wagons are off.
5. **0.5.0 Template editor** — the harness panel as an author tool: generate
   a chapters × backgrounds template (pasted URLs + local fallback), add
   chapters/backgrounds, live-edit the parked background and current chapter
   properties, copy clean markup.
6. **0.5.1 Source editor** — the output becomes an editable source pane,
   two-way synced with the preview (split source ↔ preview, round-trip
   stable). Depends on 0.5.0's canonical serializer.

Each plan is a self-contained spec: DOM contract, algorithm, test matrix,
acceptance criteria. Implement one, pass its criteria, then next, then move it
to `archive/`.

## Architecture rule: one core, three subscribers

`snowfall.js` = `core` + three controllers registered as
`Snowfall.use({measure, frame})`. The scroll listener, resize handling, dirty
flags and anchor-Y measurement live only in `core`. A controller never adds a
scroll listener, never runs its own rAF, never measures layout in `frame()`.
If `core` is absent (engine disabled, JS off) every controller is inert and
the page is still readable prose.

```js
Snowfall.create({scope, enabled, onFrame}) // instance; auto-booted as Snowfall.default
Snowfall.use({measure, frame})  // register controller, called in that order
Snowfall.refresh()              // re-collect + re-measure on next frame
Snowfall.step()                 // one manual frame (tests and QA probes drive this)
Snowfall.anchorY(el)            // document-order Y of el, marker-based, valid until refresh
Snowfall.wagons                 // {n, els, y, free, pos, ext, dir}
Snowfall.debug                  // same arrays + writes-last-frame + styleN, eventN
Snowfall.options                // {wagons, morph, events, hysteresis, parkedAsView} — all numeric
inst.setEnabled(bool)           // pause/resume without losing anchors
inst.destroy()                  // detach listeners (SPA unmount)
```

## Layout contract (hard requirement)

- Wagons stay **in flow**: `position:sticky;top:0;z-index:-1` on `.snow-bg`.
  `z-index:-1` puts the wagon below in-flow (non-positioned) text — DOM order
  alone cannot do that, because a positioned wagon otherwise paints above
  loose text. Wagon-vs-wagon order is still document order (later over
  earlier). `.snow-stick{z-index:5}` and fixed HUD stay above.
- Text containers (`section`, chapter divs) must be **transparent**: a
  `z-index:-1` wagon also paints below any ancestor background, so an opaque
  chapter background would veil the picture. Readability over busy pictures
  comes from `text-shadow`, not boxes.
- No author or harness CSS may put `overflow:hidden|scroll|auto` on an
  ancestor of a wagon or stick element — a non-visible overflow creates a
  scroll container that traps `sticky`. Horizontal safety uses
  `overflow-x:clip` (clip never traps sticky).
- A wagon is `pointer-events:none` and transparent to clicks; text above it
  stays selectable.
- `#app{position:relative}` and page colour on `html` (never on `#app`), so
  wagons behind transparent text stay visible and the morphing colour shows
  around `fixed`/`auto` boxes.
- Keep `#gen`/`#diag` panels outside `#app`: the engine collects from `#app`,
  and fixed panels must not be measured as anchors.
- Document order is logical order for wagons, stick slots, style anchors and
  scripts alike.

## Global invariants (all plans)

- Pure function of `scrollY`: same `scrollY` ⇒ same transform, colour, class —
  independent of direction and history. No hysteresis on set edges, no
  smoothing filters, no springs. Reversibility is a theorem of the math.
- Continuous: no wagon may jump more than one frame's scroll delta.
- Never overlap while parked; the push chain is a *ceiling*, so a wagon is
  never placed below its own anchor.
- No layout reads or writes ever in `frame()`: after `measure`, the engine
  writes `transform` and CSS custom properties only. Zero
  `getBoundingClientRect`, zero `offsetTop`, zero `getComputedStyle`.
- No allocations in `frame()`: preallocated typed arrays, reused scratch, no
  `{}`, `[]`, closures, or string concat unless the value actually changed.
- O(N) per frame with N = anchors, and N is small by construction (one wagon
  per chapter-ish), so no spatial indexing.
- Style: single tab indent, LF, early returns, flat helpers,
  `const $ = id => document.getElementById(id)`, comments only where a
  decision needs a `why`.

## How to verify

`python3 -m http.server` or open `index.html` via `file://` — both must work.
Harness presets + controls rebuild content; GUI buttons run every QA probe
with no npm, no build, no console. Scroll slow/fast/both ways; watch the
diagnostics panel. `node test/run.js` runs the headless gates: `test/math.js`
(pure scroll/colour/event math, zero dependencies — the one that must stay
green); DOM/page gates are optional dev-only extras, never required to trust
a change. Each plan's Acceptance Criteria is the gate for archiving it.

## Out of scope

- Build step, modules, npm, network images, polyfills, legacy browsers.
- Parallax speed factors (wagons never move faster/slower than their text,
  except lateral `data-dir` exit which is a different axis).
- Timeline editor, audio, typewriter text reveal, save state, i18n,
  virtualized DOM, pinch-zoom beyond `resize` recompute. (The harness-side
  template/source editor is in scope — 0.5.0/0.5.1; it edits markup, not a
  timeline.)
