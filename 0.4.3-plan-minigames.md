# 0.4.3 — Minigames

## Goal

One minigame is one `.js` file (plus an optional `.css`) that a story page
loads with a classic `<script>` tag. The file registers a plain table with the
runtime; the runtime turns a scroll event into a playable game and hands the
outcome back through the engine's existing store, so a game inherits
live/saved/default resolution, save slots and skip semantics without touching
any of it. Shipped example: `games/gamble.js` — two buttons that multiply the
purse by **0.5** or by **2**, default **×2** when the reader walks past.

Depends on: 0.4 (events), 0.4.1 (store + `ask`). Adds one engine read
primitive, `Snowfall.product(prefix)`, and one new file, `snowfall-games.js`.

## The API decision: a table, not a class

**A game is a duck-typed descriptor table — `{id, css, run, result}` — not a
class and not an instance of a base type.** The engine's own extension point
already has that shape (`Snowfall.use({measure, frame, off})`, and
`snowfall-region.js` is a fourth subscriber built on it), so a game file reads
like the rest of the repo: a flat table, one behaviour, early returns.

Rejected, and why:

| shape | why not |
|---|---|
| `class Gamble extends SnowfallGame` | There is exactly one implementation per game, so a base class is a rack of empty hooks. `extends` also needs the parent to be a global before the file parses (load-order coupling for nothing), forces `new`, and puts state in `this` where the runner needs it in a session object. The file stops being `require()`-able on its own. |
| an interface/protocol object the engine calls (`mount`/`update`/`destroy`) | A frame loop and a destroy phase are speculative: the engine owns the frame, and a game that needs one registers its own subscriber. What is left after removing them is `run` + an optional `result` — which is the table. |
| declarative markup only (`<div data-game="gamble">`, no JS) | The engine would have to own mounting, timing and teardown for every game, i.e. become a game framework. The event system already decides *when*; one line of author code (`SnowfallGames.play(...)`) says *what*, and the page keeps its own keys and totals. |
| engine-owned minigame support inside `snowfall.js` | Keeps region-style optional features out of the core: a page with no minigames never loads the runner. Same split as `snowfall-region.js`. |

The contract is intentionally small enough to state in one paragraph: **paint
into `g.el`, call `g.answer(value)`, optionally return a cleanup, optionally
paint the resolved state.** Everything else — the store key, the skip branch,
teardown, the class list — is the runner's.

## Non-goals

- No frame forwarding, no `update(dt)`, no promise/async resolution. A timed
  game owns its own ticker (or its own `Snowfall.use` subscriber) and cancels
  it in the cleanup `run()` returns.
- No asset loading, no canvas helper, no sprite/animation layer, no input
  manager. A game is DOM and CSS until a real game needs otherwise.
- No engine geometry changes, no new event, no new scroll listener. The runner
  is a measure-only subscriber and never reads layout in a frame.
- No page-global score. The purse is a pure function of the store
  (`product`), never a second accumulator next to it.

Load order in a story page (all classic `<script>`, one shared `?v=N` token):
`snowfall.js` → `snowfall-games.js` → `games/<id>.js` → the page's own script.
`test/region.js` enforces the token and the order on every page.

## The game table

```js
SnowfallGames.add({
	id: 'gamble',              /* required, unique; registration order is kept */
	title: 'double or halve',  /* optional, used by the runner's default result line */
	fallback: 2,               /* optional, what walking away pays; the page may override */
	css: 'games/gamble.css',   /* optional external sheet — resolved against the page */
	cssText: '…',              /* optional inline CSS, if a sheet is overkill */

	run: function (g) {        /* required: paint the live UI, wire the controls */
		g.el.innerHTML = '…';
		btn.addEventListener('click', function () { g.answer(2); });
		return function () { /* optional cleanup: cancel timers and listeners */ };
	},
	result: function (g, value, mode) { /* optional: paint the resolved state */ }
});
```

The session object `g` handed to `run`:

| field | meaning |
|---|---|
| `g.el` | the mount element; the runner cleared it and owns its class list |
| `g.key` | the store key this slot resolves into |
| `g.opts` | the page's flat options table (frozen `{}` when it passed none) |
| `g.id` | the game id |
| `g.answer(v)` | resolve live with a scalar; the second call warns and is ignored |
| `g.live` | true only while the reader can still act |
| `g.value`, `g.mode` | set by the time `result` runs |

A game never calls `Snowfall.ask` or `Snowfall.answer` and never writes the
store — that is what makes every game inherit the engine's rules.

## Runner rules

`SnowfallGames.play(id, {el, key, fallback, opts, done})` → `true` while the
game waits for the reader, `false` when it resolved inside the call or could
not run. `done(value, mode)` runs exactly once per resolution, in every mode —
the same contract as `Snowfall.ask`'s continuation, and the page's only hook
into the outcome.

1. **Skip paints nothing.** `play` opens the slot with `Snowfall.ask(key,
   fallback, null, done)`. In replay mode that resolves synchronously, so
   `run` is never called and no control ever exists; the runner goes straight
   to the result paint. Branching on the synchronous resolution is the whole
   live/replay split — a game must not decide it.
2. **One resolution, one teardown.** On any resolution the runner runs the
   cleanup, swaps `snow-game-live` for `snow-game-done`, calls `result` (or
   paints its own default line), then the page's `done`.
3. **`refresh()` drops live sessions.** The engine discards pending asks
   without resolving them, so the runner subscribes `{measure}` and, on every
   measure, tears each waiting session down and restores the mount's idle
   markup. An anchor still on screen re-fires its own snippet in the same
   refresh and remounts; a game mounted from a plain click handler rests idle
   instead. `Snowfall.use` accepts a subscriber with `measure` only.
4. **Height is the game's job.** Anchors are measured once at load, so a mount
   that changes flow height shifts everything below it. The example game
   paints one wrapper with `min-height`, identical idle/live/resolved; the
   runner compares `offsetHeight` around `run()` and warns once when a game
   grows its mount. The fix is CSS, or a `Snowfall.refresh()` outside the
   fire — never inside a snippet.
5. **CSS is injected at registration**, while the document is still parsing,
   once per game id (`<link|style data-snow-game="id">`). An external sheet
   that lands after the first measure re-measures once, on its `load`.
6. **No engine, no key, unknown id, no fallback** → `false` plus one
   `console.warn` where the cause is the page's. Nothing throws, nothing
   paints, and the story stays readable prose.

Class hooks on the mount: `snow-game` (a game mount), `snow-game-live` (the
reader can act), `snow-game-done` (resolved in any mode).

## Engine addition: `product(prefix)`

`Snowfall.product(prefix)` folds the same two maps `sum` reads — author `vars`
and recorded `keys` — multiplicatively, skipping non-numbers, and returns **1**
when nothing matches, so an untouched purse is unchanged rather than zero. A
minigame that pays a factor is recorded exactly like an additive one; only the
read differs. A page could derive this from `exportJSON()`, but then every
story would parse its own save to draw a total.

## Score semantics

- Purse = `BASE × Snowfall.product('mult.')`. The page writes nothing; the
  engine records the reader's call, the replay of an earlier one, and the
  fallback a skipped seat pays.
- Re-answering a seat **replaces** its factor; it never stacks, because one
  key holds one value. `store.counts.keys` stays at one entry per seat.
- A seat re-offers only after its anchor has left through the bottom, so a
  re-pass may leave an on-screen seat holding its earlier call. That is the
  0.4 re-arm rule, not a minigame rule.
- `default` is the game's declared `fallback` unless the page passes its own,
  and the fallback binds when the slot opens: a seat already pending from the
  load-time `view` pays the value it was asked with.
- Clearing the save folds back to the identity, so the purse returns to
  `BASE` — a multiplicative score does not zero out.

## Demo page contract

`demo-minigame.html`, `data-story="demo-minigame"`: a sticky purse HUD and TOC
outside `#app`; a short cover (so seat 1 stands in the load viewport and fires
`view` on the first frame); two seats, each a `.game` mount with an idle
placeholder plus one `<script type="txt" event="view,skip">askGamble(k)</script>`;
exact-viewport `.spacer`s; a tally on `center,end,skip`; `save ↓ / load ↑ /
clear save / self-test`; `<output id="qa">` last inside `#app`.

```js
window.askGamble = function (k) {
	if (!hasGames()) return;                 /* engine or runtime absent: stay idle */
	if (SnowfallGames.play('gamble', {
		el: box(k), key: 'mult.g' + k, opts: { ask: ASK[k] },
		done: function (v, mode) { mark(k, v, mode); }
	})) mounts++;                            /* true only on the live path */
};
```

`.game` reserves `min-height`, the HUD breakdown stays one line, and nothing
above an anchor changes height after a fire — so the page never calls
`refresh()` except in the clear-save recipe (`scrollTo(0,0)` → `reset()` →
idle markup → `refresh(true)` → redraw), where the order is load-bearing.

## Acceptance criteria

- [x] A minigame is one `.js` file plus an optional `.css`, loaded with a
      classic `<script>`; no build, no modules, `file://` friendly.
- [x] The game table is the only contract: `{id, run}` is enough to ship one.
- [x] `×0.5` and `×2` buttons; `×2` is the default a skipped seat pays, and the
      game — not the page — declares it.
- [x] `live`, `saved` and `default` each demonstrated and labelled.
- [x] A skip or a flick paints no controls and still records an outcome.
- [x] The purse is exactly `BASE × product('mult.')`; `vars` stays empty.
- [x] Re-answering replaces a factor; `counts.keys` stays one per seat.
- [x] A live session does not survive `refresh()`: cleanup runs, idle returns,
      an on-screen seat remounts.
- [x] Runtime absent or engine absent: readable prose, idle placeholders,
      starting purse, zero console errors, self-test reports SKIP.
- [x] `node test/run.js` green with `test/games.js` and
      `test/demo-minigame.js` included; no new gate skipped.
- [x] No scroll listener, no rAF loop, no `IntersectionObserver` in a game or
      in the page; the runner reads layout only around `run()`.

## Pitfalls

- **Never let a game decide the live/replay branch.** `play` returns false
  when the slot resolved inside the call; a game that paints controls
  unconditionally draws buttons a skip can never answer.
- **The mount must not change flow height.** Buttons appearing in an
  unreserved box shift every anchor below it, and the only symptom is events
  firing a screen early. Reserve the height in the game's own wrapper.
- **`refresh()` is not a resize event for a pending game.** It discards the
  ask without resolving it, so a session that outlives it keeps its timers and
  its dead buttons. The measure subscriber is what closes that hole.
- **A measure-only subscriber is legal, but a `frame`-less one used to throw**:
  `coreFrame` called `subs[i].frame` unguarded. Both hooks are optional now.
- **`css` resolves against the page, not the game file** — classic scripts have
  no module URL. A game reused from a subdirectory needs its own path.
- **A multiplicative score has no zero.** `product` of nothing is 1, and
  clearing the save returns the purse to its base; a HUD that formats the
  purse must not assume an additive total's `0`.
- **The fake DOM is part of the contract.** Its `innerHTML` getter has to
  serialize children built by `appendChild`, and its parser has to keep
  inter-tag text, or the runner's idle-restore reads back an empty string and
  the gates pass for the wrong reason.
- **Give a test page a trailing spacer.** Without one, the last seat's anchor
  sits at max scroll — inside the viewport — and a "flick" scenario mounts a
  game by accident instead of skipping it.
