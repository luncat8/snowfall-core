# 0.4 — Scroll Script Event System

## Goal

Declarative `<script type="txt" event="…">` blocks that fire at exact scroll
states — `view`, `center`, `parked`, `end`, `skip` — so a visual novella can
log, flip state, or mutate light DOM per chapter without writing a single
scroll listener. `file://` safe, inert until the engine runs them.

## Non-goals

- Not a DSL, not renpy-like: the body is plain JS. The engine only decides
  *when*.
- No per-frame execution: events are edge-triggered, once per crossing.
- No async, no `import`, no modules, no promise chains inside snippets.
- Not an animation trigger system (that is 0.3's job, driven continuously).

## DOM contract

```html
<section id="ch3">
	<div class="snow-bg" style="background-image:url(…)"></div>
	<h2>3</h2>
	<script type="txt" event="view">Snowlog("ch3 view (bottom of screen)")</script>
	<script type="txt" event="center,parked">Snowlog("ch3 centre and parked")</script>
	<script type="txt" event="end">document.documentElement.dataset.chapter="3"</script>
	<script type="txt" event="skip">Snowlog("ch3 skipped by fast scroll")</script>
</section>
```

- `type="txt"` ⇒ the browser treats it as a data block and never executes it
  (that is the whole trick; no execution of markup at parse time).
- `event` is a comma-separated list — `event="center,parked"` registers the
  same body on two events. One body per event keeps authors honest about which
  threshold they mean.
- Events, relative to the script's own anchor `Y` with `d = Y − scrollY`,
  `vh = innerHeight`:
  - `view` — overlaps the viewport: `d < vh && d >= 0` edge… precisely: the
    anchor line is on screen: `d < vh && d >= 0`.
  - `center` — crosses the reading line while on screen: `d < vh * 0.5 && d >= 0`.
  - `parked` — its wagon is pinned at the edge while the anchor is on screen:
    `pos[w] == 0 && free[w] <= 0 && d < vh && d >= 0` (Option B — without the
    viewport gate, huge chapters fire `parked` while the script sits far below
    the fold and `view`-first order breaks).
  - `end` — left past the top: `d < 0`.
  - `skip` — `end` became true while `view` had never fired: the user jumped
    past the topic, so run the fallback/default actions.
- Association: a script's `parked` target is the **last wagon whose marker Y
  is ≤ the script's Y** (`lastIndexLE` over wagon anchors) — i.e. the picture
  that is on screen where the script sits, whether or not it is inside a
  section. No such wagon, or wagons disabled ⇒ `parked` never fires
  (fallback alias to `view` only when `Snowfall.options.parkedAsView = 1`).
- Multiple scripts per event per anchor: all run, in document order.
- Free-floating scripts (outside any section) are first-class: the trigger
  point is the script's own position, not a parent's.

## Anchor measurement

`<script>` is `display:none`, so `getBoundingClientRect()` is a zero rect at
the document origin — measuring the element directly is meaningless.
Contract: reuse `core`'s marker helper (`<i class="snow-a">` inserted before
the script, `Snowfall.anchorY(el)`), which also fixes the identical problem
for `[data-bg]` blocks and gives `parked` the same Y scale as wagons. `H` is
**0 for scripts**: the trigger is the script's own line. `end` therefore
means "the line the author put the tag on has left the top of the screen" —
and the author moves the trigger by moving the tag (last line of the topic =
"topic is over"). No section-height heuristics. `view`/`center` require the
anchor to still overlap the viewport, which is what makes `skip`
distinguishable from `end` after a flick.

## State & frame

Preallocated per anchor: `Uint8Array flags` of
`SEEN_VIEW|SEEN_CENTER|SEEN_PARKED|SEEN_END|SEEN_SKIP`, plus a flat
`Int32Array` linked list of compiled function indices. No per-frame object
literals: firing walks the flat list.

```js
for (let i = 0; i < n; i++) {
	const d = y[i] - scrollY;
	if (d < vh && d >= 0) { if (!(f[i]&1)) { f[i]|=1; fire(0,i); } }
	if (d < vh * 0.5 && d >= 0) { if (!(f[i]&2)) { f[i]|=2; fire(1,i); } }
	if (d < 0) { if (!(f[i]&8)) { f[i]|=8; fire(3,i);
		if (!(f[i]&1) && !(f[i]&16)) { f[i]|=16; fire(4,i); } } }
	else if (f[i]&8) f[i]&=~8;                 // re-entered from top: re-arm end,
	                                          // view/center stay latched (no spam)
	if (parkedOk(i) && !(f[i]&4)) { f[i]|=4; fire(2,i); }
}
```

- Set on the forward edge, cleared only after `hysteresis` px of clear space
  on the *opposite* side (`d > vh + 40` clears `view`/`center`/`parked`/`skip`
  (and `end`); `d > vh*0.5 + 40` clears `center`). Hysteresis on reset only — on the set
  side it would delay events by 40 px, which is visible.
- `end` is cleared as soon as the anchor is back in view, and
  `view`/`center`/`skip` are then pre-consumed, so scrolling up and down
  across the top edge does not spam `view` on every re-entry. `parked` is
  one-shot per pass: **not** cleared on unpark (`pos != 0`), so reverse
  scroll stays silent when the wagon parks again on the way up; it **is**
  re-armed when the script leaves through the bottom (`d > vh +
  hysteresis`), so a second forward read can fire it.
- Replaying the story's history on load is a real bug (browser scroll
  restoration or a mid-document `#hash`): at `init`, anchors **already past**
  (`Y < scrollY`) are pre-set to `VIEW|CENTER|PARKED|END|SKIP` and nothing
  fires for them. Anchors standing **inside the load viewport** are not
  latched: the reader is looking at them, so the normal pass fires their
  `view`/`center`/`parked` in that same first frame, live. Latching those
  instead makes a first-screen script dead forever — `skip` is suppressed
  while the anchor's `view` bit is set, and an anchor with `Y <= vh` can
  never re-arm (`d > vh + hysteresis` is unreachable from the top). A replay
  flag disables the pre-fill entirely for testing, and `refresh()`
  re-applies it.
- O(A) integer compares per frame; A ≤ a few hundred is free. `frame()` runs
  after wagons' `pos[]` is written (subscriber order), so `parked` is accurate
  in the same frame — never fire from the scroll handler directly.

## Compilation (`init`/`refresh`)

```js
const code = el.textContent.trim();
if (!code) continue;
try { fn = new Function('Snowfall', 'detail', code); }   // page scope, no modules
catch (e) { console.error('Snowfall event script', e); continue; }
```

- One `Function` per (script, event) pair; store in `fnList`, index in the
  flat linked list. Errors are logged once with the anchor's Y; other scripts
  keep working.
- Body is left in the DOM (inert by type, and `view-source`/devtools stay
  honest); CSS hides it. A compiled `data-snow="view:1 skip:0"` attribute is
  written on fire for QA only, never read back — so `frame()` still does zero
  reads. Do not `el.remove()`: it destroys the author's document for no gain.
- `detail` is one reused frozen-shape object
  `{el, event, y, scrollY, wagon, morph}` mutated before each call (fired
  synchronously, so sharing is safe and keeps the "no allocation in the hot
  path" rule true).
- No sandbox illusion: snippets run with full page privileges. That is the
  design (author writes their own page); do not add `iframe`, `Worker`, or
  CSP handling for `file://`.

## Test matrix (0.1 harness, `events=on`)

- Slow full pass: `view→center→parked→end` per chapter, exactly once each.
- Flick to bottom: skipped chapters fire `skip` + `end`, never `view`/`center`.
- Reverse: no new events while going up; re-entering from the top consumes
  `view` silently; leaving from the bottom again re-arms `view`.
- Two scripts on one event at one anchor: both run, DOM order (assert via
  `Snowlog` sequence).
- Free-floating script between two text lines outside any section: fires at
  its own Y (±2 px), independent of its neighbours' sections.
- Broken snippet (`let =`): one console error, its siblings still fire,
  wagons and morph unaffected.
- `wagons=0`: `parked` never fires (and with `parkedAsView=1` it fires with
  `view`) — assert exactly the configured behaviour.
- Reload mid-document: no event fires for an anchor above the viewport; the
  anchors standing on screen fire their `view` (and `center`/`parked` if
  their thresholds are met) in that first frame, live.

## Acceptance criteria

- [ ] Each declared event fires exactly once per forward pass at its
  documented threshold, ±2 px, verified by QA probe `qEvents()`.
- [ ] `skip` fires only when `view` had not fired before `end`.
- [ ] Reverse scroll fires nothing new; re-crossing forward after the
  hysteresis margin fires again.
- [ ] A syntax/runtime error in one snippet is isolated: logged, others fire,
  wagon and style engines unaffected (frame loop never dies — check FPS).
- [ ] Works for section-bound and free-floating scripts alike.
- [ ] `file://`: executes with no CSP/module error; with the engine removed
  the snippets stay inert and visible in the DOM.
- [ ] No events fire on load regardless of restored scroll position.

## Pitfalls

- No `IntersectionObserver`: it reports layout position, so it cannot see
  `parked` (a transform state) and its callbacks are batched/coalesced — they
  would fire late and unreliably on flicks. `scrollY` math is exact and free.
- Never fire inside the scroll handler directly; batch in `frame()` after
  `pos[]`.
- Hysteresis belongs on the reset edge only, and `parked` must be in the
  reset mask — leave it out and a second forward pass never fires `parked`
  again. Do **not** clear it on `pos != 0` (re-fires on reverse scroll).
- `type="txt"` must never be replaced with `type="text/plain"` + `eval`: same
  result, worse error line numbers.
- `refresh()` must re-collect and recompile: after regen, stale `Function`s
  pointing at removed nodes would fire on phantom anchors.
- Guard `Snowlog` absence: snippets must not hard-require harness globals to
  work in a real story page — document `detail` as the engine-provided API.
- QA probes that walk the document consume latches: `qEvents()` must
  `refresh()` at the top before a slow pass and again before a flick, and the
  slow walk must include `scrollHeight − innerHeight` (a `+= step` loop can
  stop a few px short of the last `end`).

## Implementation notes (0.4 done)

- **Pre-fill in frame, not measure:** `eventsMeasure(replay)` only sets
  `E.needPrefill = !replay` and zeroes flags. The first `eventsFrame` after
  the refresh does the pre-fill (`pos/free` are fresh there — wagonsFrame
  runs before eventsFrame in the same coreFrame). `refresh(replay)` passes
  through; `engRefresh(replay)` does too. Cold reload mid-doc latches the
  chapters above the fold only — the ones on screen fire their `view` in that
  frame (a snippet must therefore already be defined when the engine's
  deferred boot refresh runs; `boot()` waits for `DOMContentLoaded` when the
  document is still parsing, which is every classic `<script src>`). QA
  `refresh(true)` at the top skips pre-fill (simulates arrival from the very
  top). `E.side` is still initialised for every anchor in that frame so the
  `both` direction logic sees the true side.
- **`parked` requires the anchor on screen (Option B):** the engine fires
  `parked` only when `0 <= Y − scrollY < vh` **and** the wagon is pinned.
  The spec pseudocode had no viewport gate, but without it huge chapters
  fire `parked` while the script sits far below the viewport, `view` no
  longer fires first, and re-arm plus a still-pinned wagon fires `parked`
  on the reverse leg. QA threshold probe covers `parked` via the same
  ±2px `flags` walk as `view/center/end`.
- **Anchor sharing:** scripts within 1px share one anchor; the anchor ORs
  all five `decl` bits, so a sibling `view` suppresses the anchor's `skip`
  even for a `skip`-only script (prevents `skip+end` after slow).
- **Alias `parkedAsView`:** when wagons are off (`options.wagons == 0`)
  and `parkedAsView == 1`, `parked` fires with `view` (same frame, view
  first). Covers the "events only" acceptance case.
- **`ensureMarker` reuse:** markers are now reused across refreshes
  (previously one orphan `<i>` per anchor per refresh). Same Y, no DOM
  growth on resize/probe refreshes.
- **QA `qEvents`:** slow 200px pass at top→bottom with `refresh(true)`;
  `parked` may be 0 on overlapping (`gap=0`) layouts where the chain never
  pins — the probe simulates the chain on the slow samples and only fails
  a missing `parked` when the simulation pins; reverse leg must add zero
  LOG entries; second slow pass without refresh checks hysteresis re-arm
  (full re-fire only when anchor `Y > vh + hysteresis`, else `end`-only);
  flick 0→bottom checks `skip+end` on middle chapters; thresholds walk 1px
  around `events.flags` (±2px for `view/center/end/parked`); `wagons=0`
  then `parkedAsView=1` partial walks; `console.error` spy expects exactly
  one broken-snippet error per refresh.
